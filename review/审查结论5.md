## 一、已确认通过

1. **分子与母体真正统一**

   `core_session_set` 直接来自 `core_run_session_ids(labeled)`；真实事件和每个置换种子的事件会话都被限制到该集合。`real_has`、`perm_has`、均值差和 bootstrap CI 基于同一个会话数组构造。

   这次不是"当前数据恰好没有母体外事件"，而是即使未来出现母体外事件，也会在计数前被过滤。

2. **回归测试具有实际杀伤力**

   新增测试构造了：
   - 核心母体会话 C；
   - 真实 core 阶段不活跃、但置换后可能产生 core 事件的母体外会话 X；
   - 至少一个种子必须在过滤前捕获母体外事件；
   - 过滤后计数必须等于 `perm_has` 行和；
   - 真实率、各种子置换率及 diff 必须与布尔矩阵重新计算结果一致。

   因此，删除过滤、改错母体或恢复旧计数路径，测试都会失败。

3. **冻结产物与实现一致**

   远端结果文件：
   - `bootstrap_n_sessions = 2941`
   - 真实核心事件会话率：11.8667%
   - 置换均值：7.2311%
   - 差值：4.6356pp
   - 95% CI：[3.5249, 5.7577]pp
   - 三个种子的母体外会话数均为 0
   - 过滤前后总计均为 638 个置换事件会话

   因此可接受：**[3.52, 5.76]pp 为当前 K1 置换负对照的最终冻结 CI**。

## 三、非阻塞防御性改进

`permutation_negative_control()` 在 `n_core == 0` 时会对空的 `real_has` 和 `perm_has` 求均值，产生 NaN。对当前 2,941 会话无影响，但 E0-Full 硬切分/分池/月份子集可能遇到零合格会话。建议在 E0-Full 接入前增加显式处理：

```python
if n_core == 0:
    return {
        "evaluable": False,
        "reason": "no_core_sessions",
        ...
    }
```

属于 E0 工程健壮性，不要求重跑或改写 K1.2.2 冻结数值。
