# 下一步工作方案：正式启动 E0-Full

## 一、当前项目处于什么位置

目前已经完成了第一轮最重要的“早期证伪”工作：

* K1-M 主机制门：**Go**
* K1-X 外部边界：**方向一致，但证据较弱**
* K1 总体：**条件 Go**
* pilot—实际响应持续差异已经在冻结样本、冻结阈值和负对照下得到支持
* A2“上一周期实际功率”能够缓解问题，但没有消除全部候选
* 主专利方向已初步收敛为：

> **充电响应状态识别 → 短时可执行功率区间 → 支持域内有界修正 → 支持域外保护回退**

当前 K1 报告明确规定，下一步必须先完成 E0-Full 的全量数据冻结和硬切分复现；在此之前，不得主张“其他车辆可吸收余量”，也不得输出储能、光伏或闭环控制收益。

最新主分支仍处于 K1 收尾提交 `257b11c`，说明目前尚未正式进入新的实验阶段。

同时存在三个工程治理缺口：

1. `patent_preexperiment/README.md` 仍为空；
2. 总流程决策 Issue #1 仍处于 open；
3. 尚未建立 E0-Full 的预注册配置、任务分解和证据台账。

因此，**下一步不是直接跑2GB全量数据，也不是开始写E2模型，而是先完成E0-Full阶段启动冻结。**

# 二、下一阶段的唯一目标

E0-Full 要回答的不是“模型能做多复杂”，而是三个更基础的问题：

1. 当前 K1 发现的问题，能否在全量、严格时间切分的数据上复现？
2. 当前候选机会，是否仍不能被最强简单基线消除？
3. 数据底座是否足够可靠，可以支持后续 E1-Full 和 E2，而不会出现泄漏、样本漂移或统计口径变化？

E0-Full 的批准范围继续限定为：

* 数据注册；
* 完整性和质量校验；
* 硬时间切分；
* 标准化数据集构建；
* K1 指标复现。

不包括：

* 主动增配模型；
* 可吸收余量估计；
* 复杂时序模型；
* 多车优化调度；
* 闭环收益仿真；
* 储能、光伏或PCC效果结论。

这一边界已经在审查结论中冻结。

* 异常月份与常规test分开；

# 十一、失败时如何止损

## 情况一：D0失败

处理：

* 暂停所有模型；
* 修复数据契约、切分或质量问题；
* 不运行正式test；
* 不改变问题定义。

## 情况二：K1指标在train成立、test不成立

处理：

* 不改阈值；
* 不换月份；
* 不删除不利池；
* 不增加复杂模型；
* 召开新的门评审。

可能结论：

* 收缩场景；
* 降级为特定站点或field mode方向；
* 收缩为保护型上界；
* No-Go。

## 情况三：问题存在，但A2已消除超过80%

处理：

* 停止复杂区间模型；
* 采用A2或简单状态机；
* 只评估简单步骤组合是否仍有专利空间。

## 情况四：E1复现通过，但跨站证据弱

处理：

* 保留Caltech主场景；
* JPL继续作为边界；
* 权利要求限制适用条件；
* 不宣称普遍适用于全部车型和站点。


1. 当前功率持久性；
2. 上一周期实际功率；
3. 滚动均值、最小值和分位数；
4. pilot上限；
5. `min(pilot, rolling_quantile)`；
6. 简单状态机；
7. 线性或分位数回归；
8. 轻量树模型。

只有相对最强简单基线使高估功率电量至少下降10%，绝对下降有意义、配对置信区间下界不跨0、区间宽度受控且跨池方向一致，才能通过K2。
