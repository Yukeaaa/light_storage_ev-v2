>
> **不能把“发现某车没吃满功率 → 把剩余功率给别的车”作为核心创新。真正应该争取专利空间的是：基于可观测充电响应识别车辆当前“可执行状态”，生成短时可执行功率边界，并据此对站级预算做受约束的闭环修正，同时在证据不足或超出支持域时主动回退。**

这一区别非常重要。

# 二、重新定义最终目标：我们不是在做一个“充电算法项目”

当前 README 和 V2.0/V2.1 的顶层定义其实是正确的。

V2.0 明确写的是：

> 最终目的不是找到效果最好的算法，而是按“问题是否真实 → 变量是否可观测 → 简单方法是否足够 → 控制结果是否改善 → 能否形成完整技术步骤”来证伪或确认专利候选。

V2.1 又进一步把成功定义成：

> **可靠地选出方向，或者及时证明方向不成立，二者都是成功。**

所以我们后面的所有工作都应该围绕一个问题：

> **最终能不能写出一条有工程对象、有输入、有状态转换、有控制动作、有保护边界、有技术效果，而且与普通充电分配/预测/MPC存在结构差异的独立权利要求？**

不是：

* MAE 能不能再低 5%；
* 能不能上一套 Transformer；
* 能不能搞一个漂亮的光储充联合优化；
* 能不能把 PV/BESS/EV 全部塞进一个数学模型。

这也是之前项目最终 No-Go 后，现在这套门链最有价值的地方。V2.1 明确吸取了“预测指标不能替代控制价值”“鲁棒本身不是创新”“不同机制同解就关闭”等教训。

# 三、我们真正面对的技术问题是什么？

我建议现在把技术问题冻结成下面这个版本，以后专利、实验、汇报都围绕它。

## 技术问题

光储充站的 EMS/充电控制器在为多个 EV 会话分配功率预算时，通常知道：

* 某个 EVSE 当前允许多少；
* 当前及历史实际吸收多少；
* 一些桩侧状态；
* 当前站级预算。

但它**不知道车辆内部真实可执行能力**：

* 没有可靠实时 SOC；
* 没有 BMS 内部限功率原因；
* 不知道真实剩余需求；
* 不知道真实未来离场；
* 甚至并不是所有数据模式都有 pilot。

README 已经明确限制这些隐藏变量不能成为独立方案必要输入。

于是产生一个控制问题：

> **“分配给车辆的允许功率/预算”和“车辆短期真正会吸收的功率”之间可能长期存在差异。**

而 K1 已经证明，这不是极少数异常：

* Caltech 核心运行段事件会话率约 **11.9%**；
* 中位差约 **1.28 kW**；
* 六个月都存在；
* 时间置换负对照明显更低；
* 简单 A2 上一周期实际值虽然能消除一部分，但仍不能消除全部机会；
* Caltech A2 候选率 **21.3%**；
* JPL current-only 第二证据池为 **39.3%**。

而 claim registry 也很清楚地区分了：

**已经证明：**

`C-003` 持续响应差异存在；

`C-011` 简单上一周期实际功率可以缓解但不能完全消除。

**还没有证明：**

`C-004` 差值可被其他车吸收；

`C-007` 响应状态可识别；

`C-008` 可执行功率区间可生成；

`C-009` 支持域内修正有效；

`C-010` 支持域外回退有效。

这正是正确的科学边界。

# 四、D1-R 的创新点应该重新分层

目前仓库给 D1-R 的技术链是：

> 采集当前及历史实际响应 → 识别响应状态 → 生成未来短时实际吸收功率区间 → 作为会话分配约束 → 检测预算与实际响应差值 → 支持域内预算修正/同池重分配 → 实际响应反馈更新。

我认为这条链总体正确。

但**不是每一个步骤都具有同样的专利价值。**

## 第一层：本身不够创新

### 1. 动态分配充电功率

非常拥挤。

已有专利早已涉及多个 EV 之间根据实际充电功率动态增加/减少分配，甚至明确描述一个车辆实际需求较小，就把多余功率分给另一个车辆。CN112829627A 就属于非常直接的近邻。([谷歌专利][1])

所以：

> “检测一辆车实际功率小，然后把剩余给另一辆车”

**不能做我们的主创新点。**

### 2. 根据近期实际功率修正 limit

也已经很拥挤。

US10464435B2 已经使用近期实际供电历史来动态确定充电口功率限制，也讨论多端口作为组管理总功率预算。([谷歌专利][2])

所以单独的：

> “历史实际功率 + 功率限制调整”

也明显不够。

### 3. pilot 控制

更加不能作为创新核心。

既有专利早就根据系统条件修改 control pilot，也有直接测试 EV 对 pilot 改变响应时间的方案。([谷歌专利][3])

所以不能写成：

> “通过调节 pilot 控制 EV 功率”

这种范围太宽，基本没有竞争力。

---

# 五、真正值得我们继续追的创新核心

我现在认为 D1-R 最有价值的是**四个环节之间的组合关系**，而不是其中任何单点。

## 创新核心 A：由“响应差”识别短期执行状态

不是简单说：

`pilot - actual > threshold`

而是利用一段仅包含在线可获得数据的历史窗口：

* actual power/current；
* pilot（有则用）；
* charging state（有则用）；
* 响应持续时间；
* 连续性；
* 前一周期/滚动统计；
* 自然 pilot 变化后的历史响应；

判定车辆当前属于某个**响应状态**。

例如概念上可以是：

* 正常跟随；
* 稳态受限；
* 低吸收；
* 斜坡响应；
* 不确定/冷启动；
* 支持域外。

注意：专利最后不一定需要使用这些具体名称。

真正重要的是：

> **状态不是车辆 BMS 内部状态，而是基于桩侧可观测的输入—输出响应关系推断的“控制执行状态”。**

这比普通的“预测负荷”更有专利结构价值。

---

# 六、创新核心 B：输出的不是预测点，而是“短时可执行功率区间”

这是我认为 D1-R **最值得保护的一层**。

传统预测通常输出：

[
\hat P_{t+1}
]

我们的目标应该是：

[
[\underline P_{t+h},\overline P_{t+h}]
]

并且这个区间表示：

> 根据当前车辆响应状态和历史支持证据，在未来 1/5/15 min 内，应当把该车辆作为怎样的**可执行功率约束**交给上层调度器。

注意措辞：

目前还不能直接叫：

> “车辆物理最大可充功率”。

它只能是：

> **数据支持的短时实际响应区间 / 可执行功率区间。**

是否真能使用“可执行”这个词，就由 E1-Full + E2 来决定。

计划书本来也规定：自然 pilot 正阶跃必须证明阶跃前状态能够区分“会响应”和“不会响应”，否则 D1-R 必须收缩，不能主张主动增配。

这是非常正确的 kill gate。

---

# 七、创新核心 C：不是无限相信模型，而是“支持域内修正 + 支持域外回退”

这一点我建议未来在专利中提升地位。

也就是：

```text
当前样本
   ↓
是否落入已验证支持域？
   ├── 是 → 使用响应状态 + 可执行区间
   │         ↓
   │       有界修正预算
   │
   └── 否 → 不外推
             ↓
        历史实际功率/
        滚动分位数/
        保护上界
```

这比“AI预测未来充电功率”强很多。

原因有两个。

第一，这是**明确的控制安全边界**。

第二，它跟我们数据天然存在的多模式问题吻合：

* measured pilot；
* measured no-pilot；
* computed pilot；
* computed no-pilot；
* current-only。

因此系统可以形成：

> **证据充分时提升控制分辨率，证据不足时主动降低控制自由度。**

这个结构在工程上很合理，也比“模型置信度低所以不用”更容易形成技术步骤。

---

# 八、创新核心 D：最终控制动作必须是“有界预算修正”，不能只是预测

这是整个项目能不能成为控制专利的关键。

最终系统应该形成：

[
P^{EV}_{budget}
]

经过车辆状态识别后，得到每车：

[
[\underline P_i,\overline P_i]
]

然后：

[
P^{EV,new}_i
============

\operatorname{BoundedAdjust}
(P^{EV,old}_i,[\underline P_i,\overline P_i])
]

且满足：

* 站级总预算约束；
* 单车边界；
* 变化速率/动作次数；
* 安全限值；
* 支持域约束。

如果某车出现：

[
P^{alloc}_i > \overline P_i
]

则不是直接宣布：

> “这部分是可回收功率”。

而先定义：

> **预算修正量。**

之后才判断这部分预算：

* 返还站级 EV 预算；
* 分配给已经验证有吸收能力的其他 EV；
* 或交还站级优化器，让 BESS/PV/PCC 重新处理。

这个表述非常重要，因为它规避了目前证据尚未支持的 `C-004`。

---

# 九、因此，我建议现在把 D1-R 的专利主轴进一步冻结成一句话

相比原来的题名，我建议内部以后优先按下面这句话思考：

> **一种基于充电桩导引信息与车辆实际充电响应的状态识别方法，生成车辆短时数据支持可执行功率区间，并依据所述区间对光储充站 EV 功率预算实施支持域内有界修正，在响应证据不足或超出支持域时切换至保护型功率边界。**

真正的链是：

**响应监测**
→ **响应状态**
→ **短时区间**
→ **支持域判断**
→ **有界预算修正**
→ **保护回退**
→ **实际响应反馈**

我现在认为这比：

> “充电功率回收重分配方法”

明显更好。

因为后者的现有技术拥挤度很高。已有专利直接涉及实际充电功率驱动的多车余量分配。([谷歌专利][1])

目前 V2.1 的 D1-P / D1-A 分叉非常合理：

* **D1-P：保护型**
* **D1-A：主动重分配型**

我的建议是：

也就是：

### D1-A 暂时作为条件增强

只有后面证明：

1. 自然 pilot 正阶跃有足够样本；
2. 阶跃前状态能预测正向实际响应；

才把：

> “回收 → 接收车选择 → 再分配”

升级到核心权利要求。

否则 D1-A 很容易落入已有“剩余功率动态分配”专利密集区。

# 十四、E0F-02 到底为什么重要？

E0F-02 **本身没有创新。**

时间切分、field mode registry、role registry 都不是我们的专利点。

它只有一个作用：

> **保证后面的“创新证据”是真的。**

尤其必须防止三类假阳性。

### 1. 时间泄漏

同一车辆会话跨 train/test，未来信息偷偷进入模型。

### 2. JPL 角色污染

把 COVID 边界数据或 current-only fallback 数据拿去调模型，再称“跨站泛化”。

### 3. field-mode 混淆

pilot-rich 训练出来的结果，被错误描述成 current-only 也可用。

所以 #13 当前的设计是正确的：

* session-level split；
* 60/20/20；
* external/stress 分离；
* field_mode 与 split 分开；
* JPL boundary/current-only role 永远独立于 train 标签。

# 十六、我们接下来的三个真正杀伤门

从专利角度，我现在最关心的已经不是 E0F-02 本身，而是它之后这三件事。

## 杀伤门 1：E1-Full 自然正 pilot 阶跃

这是 D1-A 的生死门。

如果：

> pilot 增大以后，车辆响应基本不可预测、状态前无法区分，

那么：

**立即砍掉“主动吸收余量”主张。**

不是换复杂模型救它。

转为 D1-P：

> 预测短期无法执行的上界，避免错误预算。

---

## 杀伤门 2：E2 与简单方法的比较

这是 D1-R 的核心信息价值门。

真正要打败的不是神经网络，而是：

* last actual；
* persistence；
* rolling median；
* rolling quantile；
* 简单状态机。

如果复杂模型只是：

> MAE 低一点，

但高估功率没有明显改善，

那么复杂模型不要进入独权。

V2.1 对 K2 的定义本身就是“新增信息价值门”。

---

## 杀伤门 3：E4 闭环

这是主专利的最终生死门。

主指标不能是 RMSE。

V2.0 已经正确规定 D1-R 的优先指标：

> 高估/未执行功率电量 → 站级预算跟踪残差 → 交付影响 → 动作与运行时间。

如果 E2 区间预测看起来很好，但放进控制器：

* budget residual 没改善；
* 或交付变差；
* 或动作疯狂；
* 或简单 persistence 控制一样好，

**D1-R 主控制专利就应该 No-Go/降级。**

---

# 十七、到今天为止，我对专利方向的重新评级

### D1-R：继续第一主候选

**评级：条件 Go，明显值得继续。**

优势不是算法复杂度，而是：

> **实际响应驱动的控制执行边界。**

---

### D1-P：应该正式保留为强备选

**评级：很重要。**

我甚至认为它不是“失败后的残次品”。

如果主动增配证据不足，但能够稳定避免：

> “把站级预算分给短期明显不会吸收的车辆”，

并降低预算跟踪误差，那么它仍然可能形成很实用的控制专利。

---

### D1-A：高价值、高风险

**评级：等待 E1-Full。**

只有自然正阶跃证据出现，才升级。

---

### D2-R：潜在第二专利

**评级：保留。**

尤其是“不同字段可信度 → 不同边界 → 不同回退动作”如果 E5 有独立控制收益，值得单开。

---

### D3-R：目前不投资

**评级：观察。**

除非后面真的出现负迁移，否则不要为它开发复杂东西。

---

# 十八、给项目重新定一个最简“北极星”

以后每做一个功能，都问一句：

> **它是否帮助我们证明或否定下面这个技术闭环？**

```text
桩侧在线可观测数据
        ↓
识别车辆短时响应状态
        ↓
得到数据支持的功率执行边界
        ↓
限制/修正原有 EV 功率预算
        ↓
证据充分才重分配
证据不足则保护回退
        ↓
观察实际响应
        ↓
下一周期更新状态与边界
```

**这个闭环，才是现在最值得保护的东西。**

不是“AI预测”。

不是“光储充优化”。

不是“剩余功率重分配”。

不是“pilot 差值”。

而是：

> **把车辆历史实际响应转化为站级调度可直接使用、带支持域和保护回退的短时执行约束，并闭环修正 EV 功率预算。**

这也是我目前认为最有机会与已有普通动态功率分配技术拉开距离的地方。已有技术已经覆盖了实际功率驱动的动态分配和近期功率历史驱动的 limit 调整，所以我们的后续权利要求设计必须围绕**响应状态—执行区间—支持域—有界修正—回退**这一组合进一步做近邻检索。([谷歌专利][1])

---

## 审查结论15

**总体路线继续 GO。**

当前不需要重新换题，也不需要扩展新方向。

但从现在开始，主线应进一步冻结为：

> **D1-R = 可观测响应状态识别 + 短时执行功率区间 + 支持域判断 + 站级预算有界修正 + 保护回退。**

`同池回收重分配` 降为 **D1-A 条件增强**，等待 E1-Full/E2/E4 给证据；不要提前让它成为专利标题的中心。

E0F-02 可以开始，而且应该继续保持它现在的纯数据治理角色。**这一步不要增加任何模型，也不要因为我们开始讨论专利创新就偷偷把 E2 内容塞进去。**

等 E0F-02 完成后，我建议我们继续用同样方式审 #13：不仅看 split 是否正确，还检查它是否足以保证后续 **E1/E2 的每一项专利证据都无法发生时间泄漏、角色污染和测试集调参**。
