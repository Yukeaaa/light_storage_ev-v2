当前A2结果证明：

它还没有证明：

三、必须修复的K1.2.1问题
P0-1：时间置换bootstrap使用了错误的分母总体

这是本轮唯一会影响统计置信区间的代码问题。

当前点估计为：

real_rate = event_sessions / core_denom

其中core_denom是具有核心运行窗口的会话，大约2,939条。

但bootstrap使用：

sessions = labeled["session_id"].unique()

这里包含约5,961条全部会话，包括没有核心运行窗口的会话。随后在全部会话上重采样。

因此点估计与置信区间使用了不同分母：

点估计：
349 / 约2939 = 11.9%

bootstrap：
在约5961个全部会话中计算事件标记均值

这正好解释了当前异常：

真实率 - 置换率点估计 = 4.6个百分点
bootstrap 95%CI = [1.7, 2.8]个百分点

点估计4.6个百分点甚至不在自身置信区间内，统计口径明显不一致。提交结果中也同时记录了这两个数值。

正确实现
core_sessions = (
    labeled.loc[
        (labeled["phase"] == PHASE_CORE)
        & labeled["charging_active"]
        & labeled["pilot_available"],
        "session_id",
    ]
    .drop_duplicates()
    .to_numpy()
)

sessions = core_sessions

然后真实事件和三个置换结果均在同一core_sessions集合上构造布尔标记并bootstrap。

门判定也要同步修正

当前代码的pass_permutation实际只检查：

real_rate > perm_rate_mean

但报告和K1结论写的是：

bootstrap差值CI下界 > 0

应改为：

pass_permutation = diff_bootstrap_ci95[0] > 0

根据现有349个真实事件会话和约7.2%的置换率判断，修正后大概率仍会通过，但需要重新生成负对照统计。

这项修复只需重跑E1负对照，不需要重新提取真实事件。

P1-1：energy_kwh_post_done错误包含了tail能量

当前代码先定义：

done_anchored = events[
    events["event_phase"].isin([PHASE_POST, PHASE_TAIL])
]

随后写入：

"energy_kwh_post_done":
    done_anchored["gap_energy_kwh"].sum()

这会把post_done + pre_done_tail的总能量记到energy_kwh_post_done中。

结果文件已经出现自相矛盾：

n_post_done = 0
energy_kwh_post_done = 1141.1 kWh

实际上1141.1kWh是pre_done_tail能量，不是post-done能量。

修正
post = events[events["event_phase"] == PHASE_POST]
tail = events[events["event_phase"] == PHASE_TAIL]

energy_kwh_post_done = post["gap_energy_kwh"].sum()
energy_kwh_pre_done_tail = tail["gap_energy_kwh"].sum()

这项错误不影响K1门，因为post-done事件数仍是0，也不影响核心段11.9%的结果，但必须在最终证据包冻结前修复。
