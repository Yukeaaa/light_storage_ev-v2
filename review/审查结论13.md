P0-1：covered 现在只比较数量，不比较集合

目前代码是：

if len(covered) != n_registry:
    raise ...

这解决了跨月重复计数，但还差一步。

假设 registry 是：

A B C

分区因为残留文件变成：

A B X

那么：

len(covered) == len(registry) == 3

仍然会 PASS。

尤其你现在引入 finalize_existing_partitions()，它就是专门用来处理“已有磁盘输出”的，因此必须防 stale partition / stale session。

应该改成：

expected = set(registry["session_id"].astype(str))
if covered != expected:
    missing = expected - covered
    extra = covered - expected
    raise RuntimeError(...)

并报告：

missing count + first example
extra count + first example

这个属于 P0，因为当前报告已经声明：

universe = 85,877 原样继承，无 orphan session。

仅比较数量还不足以机器证明这个结论。

三、P0-2：目前“全局主键唯一”实际只检查了“分区内唯一”

报告写：

[session_id, timestamp_utc(1min)] 唯一，非法重复 hard STOP。

但代码实际只对每个 parquet 做：

df.duplicated(["session_id", "timestamp_utc"])

正常 build 下这几乎肯定没问题，因为 timestamp 决定 year/month。

但 finalize 是从已有文件读取；如果一个 row 被错误放进另一个 partition：

site=caltech/year=2019/month=03/

里面却有 timestamp 属于 2019-04，那么同一 key 可能同时存在于 03 和 04 两个文件，而两个文件各自内部都 unique。

不建议维护 28M key 的全局 Python set，太耗内存。

更好的廉价证明是 finalize 每读一个 partition 都检查：

df.site == path.site
df.timestamp_utc.year == path.year
df.timestamp_utc.month == path.month

只要：

每分区内部 key unique；
每行 timestamp 与所在 year/month 路径一致；

那么不同 month partitions 不可能出现相同 timestamp key。

这就能真正支撑“全局 uniqueness”。

四、P0-3：能量 STOP 的机器实现和冻结的 <1% 语义差一个边界

这是一个纯治理 bug，但必须修。

冻结配置和报告说的是：

median deviation < 0.01

现在代码却是：

median_abs_dev > tolerance

才 STOP。

因此：

median == 0.010000

当前会 PASS。

应该是：

median >= 0.01 → STOP

另外当前 median 先：

round(..., 6)

然后再拿这个已经 round 的值做 gate。

也不推荐。

正确做法是：

raw_median = float(abs_dev.median())

gate:
    raw_median >= tolerance

report:
    round(raw_median, 6)

也就是：

gate 用原始值，显示值才 round。

当前 Caltech 0.009748，因此修复这个边界不会改变本轮 verdict。
