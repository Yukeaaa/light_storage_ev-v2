三、仍需修复的问题
P1：置换点估计的分子尚未严格限制在核心会话母体

当前代码先在所有合格会话中运行置换事件识别：

core = _events_with_phase(perm, thr)
core = core[core["event_phase"] == PHASE_CORE]

per_seed.append({
    "core_session_rate": _session_rate(core, core_denom),
})

之后才为bootstrap定义：

sessions = core_run_session_ids(labeled)
perm_has = np.stack([
    np.isin(sessions, perm_core_frames[s]["session_id"].unique())
])

也就是说：

bootstrap中的置换事件只统计原始核心窗口会话；
但perm_rate_per_seed和perm_rate_mean的分子，可能包含不属于原始核心会话母体的置换事件会话。
为什么会发生

某个会话可能具有core_run_segment时间段，但在真实数据中该时间段没有满足：

charging_active且pilot_available

所以不在2,941个core_sessions中。

时间置换后，原本出现在其他阶段的活跃功率可能被移动到core阶段，使该会话出现置换core事件。此时：

该会话被计入置换分子
但不在core_denom分母母体中

代码目前没有阻止这种情况。

因此严格来说：

diff_real_minus_perm

仍不一定与：

diff_bootstrap_ci95

来自完全相同的会话集合。当前4.6pp碰巧落入CI，不等于该边界已被代码保证。

正确修复方式

应在进入置换循环前冻结会话母体：

sessions = core_run_session_ids(labeled)
core_session_set = set(sessions)

每个置换种子产生事件后立即过滤：

core = _events_with_phase(perm, thr)
core = core[core["event_phase"] == PHASE_CORE]
core = core[core["session_id"].isin(core_session_set)]

更稳妥的方式是不再由事件表单独计算置换点估计，而直接由与bootstrap相同的布尔矩阵计算：

real_rate = float(real_has.mean())
perm_rates = perm_has.mean(axis=1)
mean_perm = float(perm_rates.mean())
diff = real_rate - mean_perm
ratio = real_rate / max(mean_perm, 1e-9)

这样可以从代码结构上保证：

点估计母体
= 每种子置换率母体
= bootstrap母体
= core_denom

建议同时输出诊断字段：

n_perm_event_sessions_before_population_filter
n_perm_event_sessions_outside_core_population
n_perm_event_sessions_after_population_filter

便于确认本次修正到底改变了多少会话。

四、当前新增回归测试还没有覆盖这个边界

新测试已经验证：

无核心窗口会话不会进入core_run_session_ids()；
单会话情况下点估计位于bootstrap CI；
post/tail/mid能量被正确拆分。

但test_permutation_bootstrap_uses_core_sessions_denominator()没有调用真实的_permutation_control()路径，而且使用的是：

real_has = [True]
perm_has = [[False]]

在一个样本的退化情形中，CI必然等于点估计，无法检验置换事件分子是否含有母体外会话。

建议新增一个集成测试，至少断言：

result["bootstrap_n_sessions"] == core_denom

result["real_core_session_rate"] == real_has.mean()

每个perm_rate_per_seed
== 对应perm_has行的mean()

result["diff_real_minus_perm"]
== real_has.mean() - perm_has.mean(axis=1).mean()

并构造一个“真实core阶段不活跃，但置换后可能在core阶段活跃”的会话，确保其不会进入置换分子。
