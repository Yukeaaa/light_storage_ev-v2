## 0. 为什么需要本计划

A 目前在**专利机制**与**可实施性**上已足以支撑说明书全文；缺的是**有效性证据**——这正是 `A-M3–M6 = UNVALIDATED` 的含义。

**已穷尽的路线**：M5BAT 线。项目内 RD-2 已正式终判停止，且明确记载"RD-2 结果不进入专利证据链""M5BAT 对 E4 素材贡献穷尽"。因此：

> **不再用 M5BAT 承担 A 的效果证明。** 本文档不为其安排任何验证任务。

**本计划的基本判断**：不再指望"找到一个神奇公开数据集把整条专利验证掉"。原因是 A 的核心链需要的不是更多电气量，而是**偏差原因的 ground truth**——而这恰恰是公开运行数据最缺的东西。

因此把验证拆成三层（§1），并把主投入放在**能自己制造并记录原因**的试验台上（§6）。

## 1. 证据三层结构（强度阶梯）

```text
① 公开数据模块验证
   → 证明「问题与输入形态真实存在」
② HIL / 可控真值实验
   → 证明「归因、能力更新、承接、回写机制本身有效」
③ 真实站 shadow（只算不下发） → 受控闭环
   → 证明「在真实噪声与真实设备上仍成立」→ 最强的技术效果证据
```

| 层 | 能证明 | **不能**证明 |
|---|---|---|
| ① 公开数据 | 要求—执行偏差在真实系统中可被构造；特定输入形态（如通信异常注入）真实存在 | 归因是否正确（缺原因真值）；闭环效果 |
| ② HIL / 可控实验 | 在**已知原因**下，归因门、能力状态更新、跨资源承接、回写与恢复是否按设计工作 | 真实噪声/真实设备/真实规模下的表现 |
| ③ 真实站 shadow | 在真实噪声与设备上机制仍成立；与实际结果可离线对比 | 真实控制动作下的闭环效果 |
| ③′ 真实站受控闭环 | 最强的技术效果证据 | —— |

**纪律**：每一层的结论只能在本层范围内陈述；**不得**用低层的观察去支撑高层的结论。

## 2. 最低数据合同（围绕权 1【a】–【e】设计）

| # | 数据域 | 最低字段 | 服务于 |
|---|---|---|---|
| 1 | 控制要求 | `timestamp, resource_id, P_req / setpoint / constraint` | 【a】要求 vs 执行 |
| 2 | 实际执行 | `P_meas`（越高频越好） | 形成执行偏差 |
| 3 | 通信 / 数据质量 | 心跳、超时、数据新鲜度、通信延迟、缺测 / 冻结标记 | 【b】"通信问题不得误判为能力不足" |
| 4 | 响应阶段 | 指令下发时刻、响应开始 / 稳定时刻 | 区分暂态与持续受限 |
| 5 | 本地物理条件 | 当前上下限、SOC、温度、限功率状态、控制模式、保护状态 | 真实能力归因 |
| 6 | **能力真值** | 实验中人为施加的 `Pmax / Pmin` 或已知硬限值 | 判断能力状态更新是否**正确** |
| 7 | 站级量 | PCC / 关口功率、站级目标 / 约束 | 偏差 → 站级缺口；闭环效果 |
| 8 | 重分配动作 | `ΔP_cmd`、承接资源 ID、执行次序 | 【d】 |
| 9 | 反馈回写 | 修正后的实际功率；能力边界 before / after；可信度 before / after | 【e】 |
| 10 | **事件真值** | 通信异常 / 暂态 / 持续本机限值 / 外部约束 / 正常 | **验证【b】最关键的一列** |

### 2.1 最关键的一列：事件真值

**"事件真值"是公开运行数据最缺的东西。** 没有它，最多只能看到"有偏差"，**无法判断算法把偏差归因对了没有**。

因此自有站点或 HIL 采数时，最重要的不是多采几个 SOC 字段，而是：

> **每次人为制造一个已知原因的偏差，并把原因作为 ground truth 记录下来。**

### 2.2 数据频率要求

| 场景 | 要求 |
|---|---|
| HIL / 试验台 | **100 ms ~ 1 s 原始采样；1 s 作为主分析粒度** |
| 真实站（带宽有限） | 1 s 最理想，5 s 尚可；**至少保留事件时刻附近的高频窗口** |
| **下限（硬约束）** | **15 min 数据基本不能验证【b】** —— 区分"通信延迟 / 暂态响应 / 持续能力受限"至少需要秒级时间尺度 |

**时钟同步（硬要求）**：控制器、PCS、PCC、通信日志必须**统一时钟同步**。否则"暂态"与"时间未对齐"无法区分，【b】的判定会整体失效。

## 4. 实验程序：A-EV-1 ~ A-EV-5

| 实验 | 要回答的问题 | 关键设计 | 最重要指标 |
|---|---|---|---|
| **A-EV-1 归因门** ⭐ | 同样是执行偏差，能否区分"能力不足"与"不是能力不足"？ | **人工制造不同原因但相近幅值的偏差** | **错误能力更新率**、正确归因率 |
| **A-EV-2 能力边界** | 归因成立后，能力边界是否向真实可用能力收敛？ | 人为改变**已知** `Pmax / Pmin` | 边界误差、过估 / 低估持续时间 |
| **A-EV-3 跨资源承接** | A 受限后，B / C 能否**各按自己的能力状态**正确接缺口？ | ≥3 个资源 + PCC | 站级剩余缺口、承接失败率 |
| **A-EV-4 反馈闭环** | 承接资源自己又失败后，其能力知识是否被更新并触发下一次正确分配？ | A→B，随后**故意限制 B**，再转 C | 二次错误命令率、剩余缺口 |
| **A-EV-5 恢复** | 限制解除后能否避免瞬间错误恢复，并逐级恢复？ | 人为解除 `Pmax / Pmin` 限制 | 提前恢复率、恢复时延、振荡次数 |

### 4.1 A-EV-1 是核心（对照设计）

**它直接检验 A 最具区别度的一句判断**：

> **执行偏差 ≠ 能力不足。**

**设计要点**：让设备产生**几乎相同幅值**的偏差（示例：约 20 kW），但**原因完全不同**：

| 组 | 人为原因 | 归因门应有的处置 |
|---|---|---|
| 1 | 通信数据冻结 | **不**更新 capability_state（排除） |
| 2 | 命令刚下发、处于 2–3 s 暂态 | **暂缓**更新 capability_state |
| 3 | 人为把 PCS 最大放电功率 100 kW → 60 kW | **更新**相应方向能力边界 |
| 4 | 上级站级约束导致动作被裁剪 | **不**把它归因成设备固有能力不足 |

```text
同样观察 ΔP ≈ 20 kW
  通信异常        → 不更新
  暂态响应        → 暂缓更新
  持续本机功率限制 → 更新
  外部站级约束    → 不归因成设备固有不足
```

**为什么这个设计比"MAE 好 3%"更有价值**：它直接打在**发明机制**上——即【b】的归因门本身。这正是 A 与"内部状态降额"和"滚动计划反馈"拉开差距的地方。

### 4.2 A-EV-1 的公开数据对应（先做低成本版）

在 HIL 就绪之前，A-EV-1 的**负对照部分**可先用 **KIOS SUC5/S1** 完成：该场景的偏差原因是**已知注入的 MITM + FDI**，属"通信 / 数据链路"一类，**不应**导致能力边界收缩。这构成【b】的一个必要条件检验（负对照），但**不能**替代 HIL 上的正向归因验证。

## 5. 完整闭环 episode 设计（T0–T10）

**配置**（3 个可控资源 + 1 个 PCC）：

```text
资源 A：BESS / PCS
资源 B：另一台 BESS / PCS
资源 C：可控充电桩 或 PV 模拟器
PCC  ：站级功率计
控制器：真实 EMS / A 算法
```

**时序**：

```text
T0   初始化 A/B/C 各自当前能力状态（见 §7 初始化义务）
T1   给 A/B/C 下发正常控制要求
T2   人为将 A 放电上限 100 → 60 kW，但仍要求 A 输出 80 kW
T3   A 出现约 20 kW 持续偏差
T4   归因门确认：通信正常 + 已越过响应观察窗 + 本地 Pmax=60 kW 持续生效
     → 构成能力受限证据
T5   A 的上向能力边界更新至相应范围
T6   20 kW 缺口映射至 PCC；按 B/C 各自当前能力状态选择 B
T7   向 B 下发 +20 kW
T8   再人为限制 B → 获取 B 实际结果 → 回写 B 的 capability_state
T9   剩余缺口转给 C
T10  解除 A/B 限制 → 分级恢复 + 执行确认
```

**覆盖范围**：这一条 episode 即把 **【b】→【c】→【d】→【e】** 与 **权 7（级联承接失败）/ 权 9（分级恢复）** 一起跑通。

**须逐次记录**：每次人为干预的**时刻、对象、原值、新值、原因类别**（即 §2 的"事件真值"）。

## 6. Baseline 与效果分层

### 6.1 对照组（不能只用"无算法"）

```text
B0：看到执行偏差就直接缩能力边界          —— 无归因门
B1：仅根据 SOC / 温度 / 厂商当前限值做静态降额 —— 内部状态驱动
B2：只把执行误差滚到下一时段计划            —— 不维护持久 capability_state
A ：归因 → 能力状态 → 跨资源承接 → 执行回写
```

### 6.2 效果分两层陈述（避免只看跟踪 RMSE）

| 层 | 内容 | 相对谁 |
|---|---|---|
| **归因效果** | 在通信异常、暂态、外部约束等场景下，A 相比 **B0** 少发生多少"**错误能力收缩**" | 主对 B0 |
| **控制效果** | 在**真实**持续能力不足场景下，A 因掌握更可信的能力边界，在后续跨资源承接中减少多少**不可执行的二次命令**与**未补偿缺口** | 对 B1 / B2 |

**纪律**：两层必须**分别报告**，不得合成单一"综合改善"数字；不得只报 PCC tracking RMSE。

## 7. 主效果指标与预注册门槛

### 7.1 主指标（第一轮只看这两个）

1. **非能力原因导致的错误能力边界更新率**
   —— 打在【b】的创造性核心（归因门）。
2. **真实能力受限后的站级剩余未补偿功率 / 能量**
