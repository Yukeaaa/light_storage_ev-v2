## 2. 模块 ↔ 权 1 五段的对应

```text
权 1【a】 → Simulator.advance() 产出的观测（功率控制要求 + 实际执行结果 + 时序/通信/局部条件）
权 1【b】 → attribution.py    有效性与能力归因判断（五类判据；按权 3 优先级：通信 > 暂态 > 持续受限）
权 1【c】 → capability.apply_capability_update()  依偏差方向收缩对应方向能力边界
权 1【d】 → gap_carrier.station_gap()     由**确认的**执行偏差 → 等效换算 + 方向聚合 → 站级缺口
           gap_carrier.select_carriers() 可承接贡献 + 方向兼容 + 物理运行约束 + 确定性排序
权 1【e】 → capability.writeback_carrier() 承接资源执行结果 → 回写**对应承接资源**的能力状态
权 7     → algorithm 的事务级排除（缺口消失即清空；**非持久资格**）
权 9     → capability.maybe_recover()     分级恢复 + 连续确认 + 失败回退
权 12    → algorithm.AEVPipeline          六单元的软件镜像
```

**实现层细化（不构成超出权项的新类别，已在代码注释中标注）**：归因输出除权 3 显式枚举的三类外，另设 `EXTERNAL_CONSTRAINT` 与 `UNCERTAIN`；二者均落在权 1【b】"资源局部运行条件"这一上位判定信息之下，处置为**排除该偏差**或**暂缓更新**（说明书 §6.1 判据 4）。

## 3. 可控真值场景台

### 3.1 现场

```text
R0  BESS 100 kW  双向
R1  BESS 100 kW  双向（首选承接资源）
R2  充电设备 60 kW  仅吸收（单向下向）→ 覆盖说明书 §12 的单边资源形态
PCC 站级净交换量，与站点原始计划比较得到站级残差
基值：R0 +30 / R1 +20 / R2 −25  →  站点净 +25 kW
```

### 3.2 事件真值（A-EV-1 的核心对照）

**同一个约 20 kW 偏差、四种不同原因**（限值统一由该资源基值推出，保证幅值一致）：

| 场景 | 注入 | 事件真值 | A 应有的处置 |
|---|---|---|---|
| `S1_comm_freeze` | 通信/数据冻结（设备实际正常，观测陈旧） | COMM_FREEZE | 不作为能力证据；**不更新** |
| `S2_transient` | 指令下发后一阶响应（τ=8 s） | TRANSIENT | 暂缓更新 |
| `S3_local_limit_up` | 本机上向可用能力压到基值并**持续** | LOCAL_LIMIT | 确认后**更新**该方向边界 |
| `S4_external_constraint` | 站级约束裁剪动作（本机无持续限值） | EXTERNAL_CONSTRAINT | 不作为能力证据；**不更新** |
| `S5_local_limit_down` | 下向（吸收）受限 | LOCAL_LIMIT | 更新下向边界（另一侧） |
| `S6_cascade` | 承接资源 R1 随后也被持续限制 | LOCAL_LIMIT | 回写 R1 + 当前事务排除 + 重新确定承接资源 |
| `S7_recovery_ok` | 限值解除 + 上探请求 | LOCAL_LIMIT | 分级恢复 + 连续确认 |
| `S8_recovery_fail` | 上探时限值**未**解除 | LOCAL_LIMIT | **不得**误触发恢复（应回退） |
| `S0_normal` | 无注入 | NORMAL | 不应发生任何更新 |

### 3.3 与 A-EV 计划「最低数据合同」的对应

场景生成器产出的字段即 A-EV 计划 §2 数据合同的可执行版本：控制要求 / 实际执行 / 指令下发时刻 / 响应开始时刻 / 通信与数据质量 / 本机限值状态与方向 / 站级约束 / SOC / 温度 / 资源 ID / PCC 净交换量 / **事件真值**。
`ScenarioSpec` 可 JSON 序列化（`spec.to_json()`），**将来直接据此驱动真实 HIL / 台架**——即"同一份场景说明既能在合成 plant 上跑，也能在 HIL 上跑"。

## 5. 指标口径

### 5.1 主指标（**不得合成单一数字**）

**① 错误能力更新率 EMUR** = 在**注入的非能力原因**窗口内、能力边界被压到初始值以下的**样本比例**。

- 分母 = 注入的非能力原因（COMM_FREEZE / TRANSIENT / EXTERNAL_CONSTRAINT）样本数；
- 分子 = 其中"该资源能力边界已被压低"的样本数；
- 打在【b】归因门。

**② 真实能力受限后的站级剩余未补偿功率 / 能量 RESID** = 在**无探针的 LOCAL_LIMIT** episode 上，统计窗口内 |站级实际净注入 − 站点原始计划| 的均值与积分。打在【c】→【d】→【e】控制效果。

> **两点口径说明（本轮踩过后才定下来）**：
> - RESID 只统计**无探针**的受限 episode：探针场景的计划含"不可达请求"，硬算残差会把恢复能力误判成承接失败；
> - EMUR 用**样本级**而非"更新事件计数"：无归因门的策略在首个样本收缩后边界即饱和，事件计数会严重低估其错误率。

### 5.2 次指标

噪声误更新率（**事件级**，只计发生在 NORMAL 样本上的收缩动作）、能力边界估计误差、二次不可执行命令率、级联承接次数、恢复时延、恢复误触发数、PCC 剩余偏差。

> 噪声口径也踩过一次：若用"样本级"判定，会把"事件结束后尚未恢复"的状态误计为噪声错误——那属于恢复时延，不属于错误更新。

### 5.3 B2 的特殊说明

B2 不维护持续能力状态，故其 **EMUR=0 是空真**（没有能力状态就无所谓"错误更新"）；其代价体现在 RESID 上。报告中不得把 B2 的 EMUR 与 A 并列比较。

## 6. 本轮运行结果（合成场景，**非效果结论**）

10 个 episode × 4 个策略 = 40 次运行；单测 16 项全过。

| 策略 | EMUR | 分原因 EMUR | 噪声误更新 | RESID (kW) | 边界估计误差 (kW) | 二次不可执行命令率 | 级联 | 恢复时延 (s) | 恢复误触发 |
|---|---|---|---|---|---|---|---|---|---|
| **A** | **0/150 = 0.00** | 三类各 0/50 | 0/2806 | **4.03** | **0.63** | 0.000 | **1** | **15.0** | **0** |
| B0（无归因门） | **150/150 = 1.00** | 三类各 50/50 | 0/2806 | 4.03 | 0.64 | 0.044 | 0 | 15.0 | 0 |
| B1（静态降额） | 0/150 | 0 | 0 | **20.00** | **58.33** | 0.000 | 0 | n/a | 0 |
| B2（误差滚动） | 0/150（空真） | 0 | 0 | 20.00 | n/a | 0.000 | 0 | n/a | 0 |

**读法（机制层面，不是效果声明）**

1. **归因门有效**：无归因门的 B0 在四类"非能力原因"窗口内**样本级 100% 错误收缩边界**；A 为 0。差异**只**来自归因环节，因此可直接归因于【b】。
2. **跨资源承接有效**：真实受限后，A 的站级残差 4.03 kW（主要为确认延迟期），B1/B2 因为**根本不重分配**而停在 20.00 kW。
3. **持久能力知识有效**：A/B0 的能力边界最后收敛到真实可用水平（误差 0.63 kW），B1 的静态规则完全跟不上（58.33 kW）。
4. **级联与恢复**：A 检出承接资源失败并回写、级联（1 次）；恢复在探针后 15.0 s 完成（12 s 响应窗 + 4 周期确认），且**试探失败的场景一次都没有误触发恢复**（0）。
5. **存在的权衡（如实记录）**：S3/S5 中 B0 的 PCC 残差（0.41 kW）**低于** A（3.03 kW）——因为它无门即动，补偿更早。代价就是上表的 EMUR=1.00。**这正是 A-EV-1 要展示的权衡：拿"错得更少"换"动得稍晚"，而不是单点取胜。**

> 以上全部来自合成场景。**不得**作为收益结论引用。

## 7. 本轮发现并修正的实现/口径问题（方法论留痕）

原型在自检中暴露了 4 个真问题，均已修正并落在代码与单测里——这类问题不修正会**系统性歪掉指标**：

| # | 问题 | 影响 | 修正 |
|---|---|---|---|
| 1 | 单向资源语义写反（`bidirectional=False` 被当成"两侧都无能力"） | R2 全程不出力，plan/actual 整体错位 25 kW | 明确 `bidirectional=False` = **仅下向（吸收）**；单边资源覆盖说明书 §12 |
| 2 | 恢复缺"试探请求"与"响应观察窗"两道闸 | 事件结束后"无偏差"被当作恢复证据 → **误触发恢复**（恢复时延甚至为负） | 恢复须存在**超过当前边界**的试探请求，且须越过响应观察窗 |
| 3 | EMUR 用"更新事件计数" | 无门策略首个样本即饱和 → 错误率被严重低估（0.001 vs 实际 1.0） | 改为**样本级**口径 |
| 4 | 级联事件给承接资源**额外加站级需求** | plan 被抬高 → 级联残差算歪（36 kW 而非 20 kW） | 级联只**限制**承接资源，不新增站级需求 |
