## 0. 权利要求树总览

```text
CLAIM 1（独立，核心闭环）   响应证据支持状态 → 边界模式选择 → 控制权限切换
   ├─ CLAIM 2（强从属）      支持状态由近期实际功率波动/方差、历史覆盖度、响应持续性之一确定
   │     └─ CLAIM 3（强从属） 近期实际功率波动/方差的具体计算实施方式（实施例）
   ├─ CLAIM 4（强从属）      存在 pilot 时引入 lagged pilot–actual response evidence
   ├─ CLAIM 5（强从属）      pilot/BMS 能力信息不可得 → current-only history protective mode
   ├─ CLAIM 6（强从属）      历史不足 → persistence / rolling quantile / conservative bound
   ├─ CLAIM 7（强从属）      新正向响应或边界贴近 → 提高控制权限、解除保护约束（恢复）
   ├─ CLAIM 8（弱从属）      evidence supported 且 opportunity sufficient 时执行有界修正
   └─ CLAIM 9（场站级从属）  EV 边界汇总到 EV 功率预算接口，与 PV/BESS/grid EMS 对接
```

## 1. 独立权利要求（CLAIM 1，核心）

一种用于光储充站的电动汽车功率控制方法，包括：

1. 获取充电对象的实际充电电流/功率时序，以及可获得时的导引/允许电流、充电状态和
   数据可用性信息；
2. 根据至少实际响应历史的变化特征，形成当前充电对象的**响应证据支持状态**（三态：
   response-supported / protective / insufficient，Phase 2 决策1 冻结）；
3. 根据所述响应证据支持状态和当前可用信息类型，选择不同的**短时功率边界生成模式**；
4. 其中所述模式至少包括：响应信息较充分时使用 response/history-derived boundary；
   导引信息不可用时使用 history-derived protective boundary；历史证据不足时使用
   conservative fallback；
5. 根据所选择的短时功率边界，确定针对所述充电对象的**功率调整约束等级**，以确定所述
   **功率边界的应用模式**并限制基于所述功率边界实施功率预算修正的**允许范围**；
   证据不足时该允许范围仅支持保护性使用，而非无条件根据"分配功率 − 实际功率"释放差值；
6. 根据后续实际充电响应重新更新支持状态，使所述功率边界的应用模式与功率调整约束等级
   能够**降低，也能够提高**（保护降级与响应恢复）。

**核心保护点（novel combination）**：第 2 步（响应证据支持状态）→ 第 3 步（边界模式
选择）→ 第 5 步（控制权限切换）→ 第 6 步（保护降级/响应恢复）之间的技术关系。
其中 2 与 3 的耦合、以及 5 对 4 的依赖，是与全部近邻的区分边界（见
`prior_art_matrix.md`）。

## 2. 从属权利要求（CLAIM 2–9，草案）

- **CLAIM 2（强从属）**：其中所述响应证据支持状态由以下至少一种确定：近期实际
  充电功率/电流的变化特征（如波动/方差）、历史响应覆盖度、响应持续性。
  （把 variance 从独立权利要求里拿出来的概括层级——`recent_var` 只作为实施方式之一。）
- **CLAIM 3（从属，实施例）**：所述变化特征包括对滑动窗口内实际充电功率/电流
  计算方差/标准差/极差，并据此划分 response-supported / protective / insufficient
  三态等级（S1/S2/S3）。
- **CLAIM 4（强从属）**：当存在导引/允许电流信息时，所述响应证据支持状态还依据
  **滞后导引-实际响应证据**（如 lagged pilot–actual ratio）确定；并在其作为
  诊断特征时约束为仅用于观测（与 A5 中 lagged_pilot_actual_ratio 仅 diagnostic 对齐）。
- **CLAIM 5（强从属）**：当导引/允许电流与 BMS 能力信息均不可得时（current-only），
  切换至**基于历史实际功率的 protective 边界**。
- **CLAIM 6（强从属）**：当历史响应证据不足时，采用 conservative fallback
  （persistence / rolling quantile / 保守上界），不输出未受支持的区间。
- **CLAIM 7（强从属，恢复）**：当检测到新的正向响应或实际功率贴近所选边界时，
  提高 EMS 对该车辆功率预算的控制权限并解除保护约束（恢复）。
- **CLAIM 8（弱从属，可选实施方式）**：当响应证据支持状态满足预设支持条件、且
  站级存在可调整功率机会时，在所述短时功率边界限定范围内对 EV 功率预算执行
  **有界修正**。（active correction 保留但不作主权利要求必选。）
- **CLAIM 9（场站级从属，不升第二发明族）**：将各充电对象的短时功率边界汇总为
  EV 功率预算约束，并提供给园区 EMS 对接。
  （Phase 2 决策3：站级汇总保持从属实施方式；D2/D3 fusion 不拆第二独立发明族；
  日后仅按标准做法补"方法 + 系统/装置 + 存储介质"平行独立权利要求。）

## 4. 术语纪律与撰写约束（逐条对应 AGENTS.md）

- pilot 与 actual 差异：只能称"导引/允许电流与实际响应差异"，不得称"命令失败/拒绝"。
- "可吸收余量/可回收能力/可回收电量"：未经 E1-Full 自然正阶跃验证 + 新独立数据验证
  前**不得**出现在权利要求或实施例措辞中（C-004 仍 D 级）。
- "预算差值"只能以观察值表述，不得与"可回收能力"等价。
- 闭环收益（储能补偿减少/光伏消纳提高）在 E4.1 响应仿真器验证通过前不得写入实施例效果。
- `recent_var` 的撰写方向：**高波动 → 判断响应状态变化/稳定性下降 → 降低对历史边界的
  信任度 → 保护/观测状态**；严禁写成"variance 高 → 多释放功率"。

## 5. 定稿前待补

- 支持状态等级数（3 级 vs 连续分数）的概括与实施例平衡；
- "控制权限"的措辞方案（限制处理权限/边界钳制/模式切换）取舍；
- 场站级汇总（CLAIM 9）是否升级为第二独立权利要求族（D2/D3 fusion）；
- 正式新颖性/创造性/FTO 检索后（见 `prior_art_matrix.md` 检索策略）再确认主权利要求
  步骤的裁剪与合并。
