## 1. 技术领域

**写作要点**：能源管理 / 站级功率控制领域；具体涉及**可控资源实际执行结果与功率控制要求之间偏差的处理、可控资源可用能力的维护，以及站级功率缺口在多个可控资源之间的分配**。

- **定义位**：无。
- **红线**：不出现收益、效率、成本类语汇。

## 2. 背景技术

> **护栏 1 适用**：全部改为"在一些现有…中""一种处理方式是…""上述方式在处理…时，可能难以…"；**不写**对整个领域的绝对结论。**不写 claim chart**（多维对照表只留内部）。

### 2.1 一段：基于资源内部状态的降额

**要点**：一种处理方式是依据可控资源的内部状态量（例如荷电状态、温度、健康状态）确定其当前可输出的功率上限，并按该上限限制下发的功率指令。

**可能难以处理的情形**：该方式依据的是**资源自身状态**的度量，而实际系统中资源未按指令执行的原因可能并不在该资源的内部状态上——例如站级约束被触发、上级限值生效、控制模式切换、通信延迟、本地保护动作等。此时仅依据内部状态难以解释"未按指令执行"这一现象。

### 2.2 一段：执行结果回写计划的滚动修正

**要点**：另一种处理方式是获取某一时段内的执行结果，并将该结果回写到下一时段的计划中，据此滚动修正后续计划。

**可能难以处理的情形**：该方式的作用对象是**计划量**的顺延修正；对于"本次未按指令执行是否意味着该资源在该功率方向上确实存在能力不足"这一问题，通常不作区分，因而计划修正与资源能力之间的关系并不明确。

### 2.3 一段：基于模型或预测的能力估计

**要点**：还有一种处理方式是建立资源或系统的模型，以模型预测值与实际值的差异作为判断依据。

**可能难以处理的情形**：模型差异的来源可能包括模型本身误差、输入数据质量、以及外部约束变化等多种因素，而该方式通常不将这些来源进一步区分。

### 2.4 不足归纳

综上，在一些现有方案中，可能存在以下情形：

1. 资源未按指令执行时，其**原因**未被区分，从而无法判断该现象是否可以说明该资源在相应功率方向上的能力受限；
2. 资源可用能力这一知识，通常不依据**实际执行结果**持续更新；
3. 当某资源的能力被判定受限后，如何在其**他资源之间重新分配**所需承担的功率，缺乏明确的确定方式；
4. 不同资源（例如光伏、储能、充电设备）的**本地功率方向**与站级参考方向之间的关系，在缺少统一约定时不易处理。

> **起草提示**：第 1 条是全篇技术问题的起点，应与 §6 的归因判据、§3 的技术问题呼应。

## 3. 发明目的与要解决的技术问题

**技术问题**：

（1）如何在可控资源未按功率控制要求执行时，**区分**该现象的原因，并据此判断其是否能够表征该资源在相应功率方向上的**持续可用能力受限**；

（2）如何依据实际执行结果，**持续更新**各可控资源的方向化可用能力状态（能力边界及其可信度）；

（3）在某可控资源的能力受限后，如何**确定待补偿的站级功率缺口**，并基于**其他可控资源各自当前的能力状态**确定其可承接贡献，进而选择承接资源及其功率修正量；

（4）如何依据承接资源的实际执行结果**回写其能力状态**，并在资源能力恢复时按分级方式恢复。

**发明目的**：提供一种站级功率控制方法及系统，通过**对执行偏差进行有效性与能力归因判断**、**依据执行证据更新方向化可用能力状态**、以及**基于其他资源各自当前能力状态确定跨资源承接**，解决上述问题。

- **红线**：发明目的不得写成"提高…效率""提升…收益"。

- 说明【b】的作用是使"未按指令执行"这一现象与"能力受限"之间建立**经过判断的关联**；
- 说明【c】的更新对象是**该资源的持续能力知识**，其性质是随执行证据演化的状态，而非一次性的限值设定；
- 说明【d】中能力状态的作用是**确定其他资源各能承接多少**；
- 说明【e】的回写对象是**执行了本次功率修正的相应承接资源**；
- 系统侧对应权 12 的六个单元，逐一给出可实现形式（软件模块、边缘控制器、EMS 内服务等），并说明设备通信接口、EMS、边缘控制器**作为系统运行环境**，不在单元之列。

### 4.2 有益效果（功能性表述）

- 使资源未按指令执行的情形能够被区分为可与不可作为能力受限证据的两类；
- 使各资源的可用能力知识随执行证据持续演化；
- 使某资源能力受限后的功率需求能够在其他资源之间按各自当前能力状态与运行约束重新分配；
- 使可恢复的能力边界能够按分级方式恢复。

> **红线**：以上均为功能性表述，**不得**附任何量化收益。

## 6. 【b】有效性与能力归因的可实施判据（本骨架重点一）

> **本章是全篇最重要的技术连接**（"偏差 → 能力证据"的桥）。必须给出**至少五类**可实施判据，使该判断具备可实施内容。**目的 = 可实施性，不是证明效果。**

### 6.1 五类判据（每条须给出判定内容、实现方式与典型判定作用 / 处置）

> **注意：不得一律做减法（本节核心写作纪律）**。下表最后一列是**典型判定作用 / 处置**，**不是**统一的"不满足即排除"。不同判据的作用方向本就不同：有的使偏差**不能被采信**（排除），有的使判定**暂缓**（等待确认），而**资源局部运行条件**在特定语义下反而构成能力受限的**正向支持信息**。撰写时必须按**类型与持续性**区分处置，不得一刀切。

| # | 判据 | 判定内容 | 实现方式（说明书须写到可实施程度） | 典型判定作用 / 处置 |
|---|---|---|---|---|
| 1 | **数据 / 通信有效性** | 执行结果是否在有效期、是否缺测或跳变、通信是否中断或超时 | 时效窗口判定；数据质量标记；通信心跳与超时计数 | 偏差**不能被采信** → 不作为能力证据（排除） |
| 2 | **时间对齐** | 功率控制要求与执行结果的时间戳是否对齐 | 对齐窗口与容差；时间戳差值阈值 | 对齐失败即不可归因 → 不作为能力证据（排除） |
| 3 | **控制响应观察窗** | 自下发时刻起经过的时长是否已满足响应判定所需 | 观察窗时长设定；窗内是否已有稳定读数 | 未过观察窗 → 判定为**暂态响应**，暂缓更新能力状态 |
| 4 | **资源局部运行条件** | 是否存在本机限功率、局部限值激活、保护动作、控制模式切换等情形，以及上述情形的**类型与持续性** | 从资源状态与告警信息中识别上述情形，并区分**持续激活型**与**瞬时跃迁型** | **按类型与持续性双向归因**：<br>· 局部限值**持续**激活且与偏差方向**一致** → 可作为**能力受限的支持信息**（正向归因）<br>· 偏差由**临时**模式切换、保护**转换瞬间**、外部闭锁或短时本机状态跃迁引起 → **排除**该偏差或**暂缓**更新持久能力边界 |
| 5 | **偏差持续性 / 重复性** | 偏差是否在连续多个采样周期或多次下发中重复出现 | 持续判定条件与窗口；迟滞（权 4） | 未满足持续性条件 → 暂缓更新，等待确认 |

**正向归因示例（须写入说明书）**：

```text
本机相应方向持续限功率已激活
+ 时间对齐正常
+ 已过响应观察窗
+ 偏差持续存在
→ 可构成"当前方向持续可用能力受限"的归因支持信息
```

**负向（排除 / 暂缓）归因示例（须写入说明书）**：

```text
临时模式切换 / 保护转换瞬间 / 外部闭锁 / 短时本机状态跃迁
→ 该偏差暂不能用于更新持久能力边界（排除或暂缓）
```

### 6.2 判定输出与后续衔接

- 判定的输出是"该执行偏差**是否能够表征**相应方向上的持续可用能力受限"；
- 判定为"能够表征"→ 进入 §7 更新对应资源的**方向化可用能力状态**；
- 判定为"不能表征"→ 不更新能力状态；其中若属通信无效或暂态响应，按 §13 的组合与优先级处置。

### 6.3 强制写作要求

- **不得**只写"进行有效性与能力归因判断"一句；必须按上表展开到可实施程度；
- **不得**把判据实现写死为单一方式（如仅"通信 + 瞬态两项排除"）——权 1【b】的上位表述为"至少一种"，说明书应给出**多于一种**的实现，以与从属权（权 3）形成层次；
- **术语纪律（A/C 边界按"更新对象"划分，不靠"A 永远做减法"）**：同一份告警 / 运行信息，在 A 中用于判断"**这个执行偏差算不算能力证据**"，其输出**仍然是能力状态**（方向化可用能力状态）；在 C 中用于决定**设备控制资格**，其输出是资格 / 准入。因此 **A 既可以做正向归因，也可以做负向归因（排除 / 暂缓），但不得把归因结果变成资格等级或资源集合准入**。相应地，**不得**写成"因存在该情形而降低该资源参与控制的程度"（那是 C 的语义，协调 V1 §4.1）。

## 7. 方向化可用能力状态与更新

**要点**：

- **结构（层级须与权 1 → 权 5 一致，不得在术语层收窄）**：

  ```text
  母概念  方向化可用能力状态 = 能力边界（限定在「至少一个功率方向」上）+（可选）对应可信度
  优选实施  可双向调节的资源 → 上向能力边界 + 下向能力边界，二者可独立更新
            仅单向调节的资源 → 仅设置对应功率方向的能力边界
  ```

  **不得**把母概念限定为"必须双向"——那会把权 1【c】为单边资源（如单向充电设备、单侧受限的光伏）留出的覆盖面在说明书层面收回。
- **方向（权 5，优选实施）**：在设置双向边界的资源中，上向与下向边界**相互独立**地更新与维持；按执行偏差的方向仅更新其中一个方向，另一方向及其可信度保持不变；
- **更新依据**：**执行证据**（经归因判断确认的执行偏差），不是内部状态量的直接映射；
- **更新对象**：**该资源自己的**持续能力知识；不得被写成对**本次控制事务**状态的记录（该区分见 §15 与协调 V1 的对 F6/A-M6 边界处理）；
- **恢复**：能力边界的恢复可采用迟滞（权 4），并可按分级方式执行（权 9）——每一级恢复后须经实际执行结果确认方可进入下一级；任一级不满足确认条件时暂停并回退至该级恢复前的值。

## 8. 资源级偏差 → 待补偿站级功率缺口（本骨架重点二）

**问题**：由"多个可控资源的执行偏差"到"待补偿的站级功率缺口"之间存在一步工程换算。在 **PV / BESS / EV 混合**场景下，不同资源的**本地功率方向**与**站级参考方向**若不统一，会留下可实施性空洞。

**说明书必须写明（建议措辞）**：

> 各可控资源的执行偏差按照**统一的功率符号约定**和**预设站级功率参考点**进行**等效换算**，并按照**方向**进行**聚合**，得到待补偿的站级功率缺口。

**须展开的四项**：

| 项 | 内容 |
|---|---|
| 符号约定 | 以站级参考点为基准定义注入 / 吸收的正负；各资源的本地功率量按该约定统一符号 |
| 参考点换算 | 各资源本地功率 → 相对于预设站级功率参考点的等效量（换算关系与约定） |
| 方向聚合 | 同向累加；异向相抵后取净值。**聚合仅作用于已观测到的执行偏差**——站级 / 资源约束不参与缺口的形成 |
| 与能力状态的分工 | 缺口由**经归因判断确认的执行偏差**确定；**更新后的能力状态不参与缺口的确定**，只用于 §9 的可承接贡献与承接选择 |
| 与承接层的分工（**勿混**） | **站级 / 资源物理运行约束的作用点在 §9 承接层**——它限制的是该缺口**能否被承接、由谁承接、承接多少**；**不得**反过来改变或削减已观测出的缺口大小，否则会重新引入刚在权 1【d】修掉的因果混淆 |

**红线**：
- **不得**写成"根据更新后的方向化可用能力状态确定站级功率缺口"（因果倒置）；
- 权 10 的"预设站级功率参考点为并网点或关口 + 关口二级确认"应作为**优选实施方式**在本章末或 §14 展开，并说明其为一种实施形式而非唯一形式。

## 9. 跨资源承接与功率修正量确定

**要点**：

1. **承接候选**：为**其他可控资源**（与产生偏差的资源相区分）。说明：实际重分配时**不排除**同时继续利用原资源仍然存在的剩余可调裕度——但独立权要求至少存在一个与产生偏差资源不同的承接资源（14 号 §6 Open item 1）。
2. **可承接贡献**：基于**其他可控资源各自当前的方向化可用能力状态**重新确定其相对于预设站级功率参考点的可承接贡献。
   > **对象归属**（15 号修订要点）：是**各承接候选自己的**当前状态，不是产生偏差资源的状态。
3. **方向兼容性判断**：按待补偿缺口的方向筛选方向兼容的候选。
4. **承接选择**：基于可承接贡献与**资源物理运行约束**选择至少一个承接资源及其功率修正量（权 1【d】）；可采用预设的**确定性排序规则**（权 6，在方向兼容的所述其他可控资源中依序选取）。
5. **级联承接失败**（权 7）：承接资源的实际执行结果不满足确认条件时，在**当前功率修正事务中**将其从后续承接选择中排除，重新确定承接资源以承接剩余缺口；在重新确定之前，维持该承接资源经实际执行结果修正后的能力边界。
6. **无可承接或仍有剩余缺口**（权 8）：按剩余缺口**调整所述多个可控资源的功率控制要求，以减小当前要求的调节幅度**，并记录调整事件与剩余缺口的方向与大小。
   > **对象体系**：本章内所有降级 / 调整动作均作用于权 1 已定义的"**功率控制要求**"，**不引入**"站级功率控制要求 / 站级目标功率"这类未定义对象（"站级目标功率"仅在权 11 作为实施形式出现）。

**A 与 C 的边界（协调 V1 §4.2）**：本章的候选排除是**事务级选择排除**（本轮 / 本次不再选作承接资源），**不是**设备持久资格或资源集合成员资格的变更。写作时不得使用"移出可控资源集合""资源准入"等表述。

## 10. 执行反馈回写与能力状态初始化（本骨架重点三）

### 10.1 回写对象（16 号修订要点）

- 反馈来源：**所述承接资源**执行相应功率修正量后的实际执行结果；
- 回写对象：**对应承接资源**的方向化可用能力状态；
- 逐承接资源对应——多资源场景下逐资源一一对应，不交叉回写；因存在权 7 的级联承接，承接资源可能不止一个，反馈对象相应为多个。

### 10.2 回写内容

- 更新能力边界，和 / 或更新对应可信度；
- 说明回写的是**该资源自己的持续能力知识**，与本次控制事务的执行状态（送达 / 确认 / 失败 / 回退等）不是同一对象。

### 10.3 能力状态初始化（**本骨架重点三**，14/15/16 号登记的义务）

**问题**：权 1【d】使用"其他可控资源**各自当前**的方向化可用能力状态"，但**首次**发生某资源能力受限时，其他资源的能力状态从何而来？

**说明书必须写明（建议措辞）**：

> 各可控资源的方向化可用能力状态在初始时刻可依据该资源的**额定能力、本地限值、最近一次经实际执行结果确认的能力边界、或预设的保守值**中的至少一种确定；此后依据实际执行结果持续更新所述方向化可用能力状态。

**须给出的两条路径**：

| 路径 | 适用条件 | 初始化取值 |
|---|---|---|
| **有历史** | 该资源曾有过经确认的执行证据 | 最近一次**经实际执行结果确认**的能力边界（可携带其可信度） |
| **无历史** | 首次投入或历史不可用 | 额定能力、本地限值、或**预设的保守值**（保守值应说明其取值原则） |

并说明：初始化值是否携带初始可信度、以及初始值与后续执行证据更新之间的关系。

  > **红线（数据事实纪律）**：**不得**为本数据源补写其并不具备的观测字段——尤其**不得**声称该数据提供"单元运行状态与告警信息"。§6 中依赖此类信息的判据条目，在本实施例中**只能作为设计层面的说明**（即在具备相应信息时如何实施），**不得**写成对该数据已实施的操作。若确需演示全部五类判据，应另选**确实具备**相应观测的数据源，而不是给现有数据源补字段。
- **① 真实观测层可写出的事实**：由计划 / 要求类量与实际功率结果，可构造出要求—执行偏差序列，并可在离线条件下统计其分布特征。
  > **用途限定与不越界表述**：该观察仅用于说明"**要求—执行偏差在真实运行序列中可被构造出来**"这一实施前提。
  > **不得**表述为"证明执行偏差确实存在、且不能由资源内部状态量直接解释"——后一表述**超出已完成的验证范围**（既有工作只考察了特定少数状态量，不等于排除温度、本地限值、保护状态、控制模式等其他内部状态）。相关结论与统计量**只进内部证据档**，不进正式文本。
- **② 设计演示层应写出**：由要求与实测确定偏差 → 按 §6 判据归因 → 按方向更新能力状态 → 按 §8 换算与聚合得到站级缺口 → 按 §9 选择承接资源并形成功率修正量 → 按 §10 规划回写；给出步骤化描述或伪代码。
- **诚实标注（必须写）**：本实施例的判据取值与阈值基于设计示例给出，**不构成对特定字段、取值或判定阈值的限定**；在具备相应观测信息时，可按 §6 的判据类别实施相应判定。
- **不要写**：任何闭环收益、改善幅度类结论；**不得**把任何既有研究结论写成对本申请技术方案的证明。

## 15. 可选实施方式：结合外部设备参与控制状态信息

**目的**：给出与外部"设备参与控制状态信息"协同的**可选**实施方式，为将来与他案接口留出位置。

**推荐写法**：

> 可选地，在另一实施方式中，调度器还可结合**表示设备可参与控制的状态信息**确定参与调度的可控资源范围。例如，在确定待补偿的站级功率缺口之后，进一步依据所述状态信息确定可参与调度的资源范围，再在该范围内按上述可承接贡献与资源物理运行约束选择承接资源。

**纪律**：

1. 必须用上位词「**表示设备可参与控制的状态信息**」，**不得**直接使用 C 的核心状态对象名（"控制参与资格""允许控制动作范围""完整 / 受限控制资源子集"）；
2. 必须以"可选地 / 在另一实施方式中"引入，**且不得写入任何权利要求**；
3. **不得"参见另一申请"**、**不得以另一申请作为支持来源**——本实施方式在本说明书中**写全**；
4. 本实施方式**不是**本申请必要技术特征：**删除 §15 后，§1–§14 仍完整可实施**（与 §11 强检验互为印证）；
5. §9 的承接选择**不得**以本实施方式为前提——承接候选的确定依据始终是**可承接贡献与资源物理运行约束**。
