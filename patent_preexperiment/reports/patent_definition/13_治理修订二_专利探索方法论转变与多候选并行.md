# 13_治理修订二_专利探索方法论转变与多候选并行

> 冻结时间（UTC）：2026-09-07
> 性质：对 `06_治理修订_发明设计轨与R5角色重定义.md` 的进一步修订。不改变：R5 七条启动条件、intake gate 五步、R5 = NOT STARTED 状态、core-patent = NO-GO 状态、两源不相加规则、V2.0 全部术语红线、v1 教训红线（禁止合成数据自证收益）。
> 触发：用户方法论纠正——前期把"核心专利证据升级标准"逐渐当成"所有新方向的数据准入门槛"，形成"想做专利 → 要完整真实数据 → 找不到 → 不敢设计 → 一直不动"的死循环；且把"已有相近专利"误当禁区。本修订把"发明机制设计 / 部分机制支撑 / 真实站级效果证明"三个问题拆开，并把 PD 轨从单链扩成多候选并行。

## 1. 三问拆分（核心方法论转变）

把以往混为一谈的三个问题显式分开：

| 问题 | 性质 | 是否要完整真实数据 |
|---|---|---|
| ① 能不能形成一个工程上合理、可实施的发明机制？ | 专利设计问题 | 否；可来自现场经验/标准/论文/专利缺口/公开数据/仿真与工程逻辑 |
| ② 有没有材料能支撑其中一部分机制？ | 部分验证问题 | 部分数据即可；一个数据集只验一个局部也有价值 |
| ③ 能不能证明它在真实站里效果显著？ | 证据升级问题 | 是；这才是 R5 7/7 |

今后探索顺序：

```
发明问题发现 → 机制设计 → 现有技术定位 → 用手头数据/benchmark 验证能验证的部分 → 形成专利 → 有机会再用真实项目数据升级证据
```

而不再是"没有完整真实数据 → 不准设计专利"。

## 2. 已有相近专利≠禁区（原则）

看到某专利已有"动态能力边界 / SOC 降额 / 执行反馈 / 光储充协调 / V2G / 数字孪生"等要素，**不意味方向作废**。说明这是产业真实关心的问题。真正要问的是：

> 它解决问题的"对象、状态变量、触发条件、连接关系、执行方式"是什么？我们能不能在同一热点下形成另一种技术机制？

例："动态能力边界"已有人做（SOC/温度 → 边界），仍可研究：故障状态 → 边界、执行历史 → 能力置信区间、多时间尺度 → 能力包络、通信可靠度 → 可调能力折减、设备健康度 → 服务能力、站级约束 → 设备能力反向分配。区别压在"连接点"而非"热点"。

## 3. 评审标准：五问 + "能验证哪一部分"

统一用五问筛方向：

```
① 这是实际工程里真实存在的动作/矛盾吗？
② 能不能说清设备、数据、状态和控制动作？
③ 有没有至少一种可实施机制？
④ 手头数据/标准/仿真能验证其中哪一部分？
⑤ 现有技术已经做到什么，我们还能在哪个连接点继续做？
```

第 ④ 问是"能验证哪一部分"，**不再是"能否证明整个发明"**。这两者差别很大。

## 4. PD 轨松绑（对 06 号 §3 的修订）

06 号 §3 写"PD 轨产出仅限文档；禁代码、禁 controller、禁收益量化结论"。本修订松绑两处、保留一处：

**(a) 多候选并行**：PD 轨从绑定当前五步链单条，扩成专利候选池 A–H 并行（注册表见 `reports/patent_pool/00_专利候选池注册表_A-H.md`）。当前五步链 = 候选 A，继续作为候选核心之一，不再独占路线。每个候选只做 cheap knockout，存活 2–3 个再分别形成核心/配套/防御专利。

**(b) 解除产出绝对限制**：允许 cheap-knockout 对"可验证部分"用公开数据/benchmark/仿真做量化推演；允许机制验证用小原型代码。不再强制"仅限文档"。

**(c) 保留 v1 教训红线**：**禁止在无验证证据时用合成数据/纯设计文档自证收益**（v1 错误 = 合成数据自证收益）。效果级结论（"提升/节省/效率 X%"）仍须 A 轨 R5 7/7。cheap-knockout 的量化推演只用于"能验证的部分"机制可行性，不得升级为部署级效果断言。

升级链不变：机制拆解 → PO-SEARCH 强制深查 →（达标才可）权利要求草案 → 证据等级升级仍须 R5 7/7。
