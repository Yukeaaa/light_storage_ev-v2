# 06_治理修订_发明设计轨与R5角色重定义

> 冻结时间（UTC）：2026-09-06
> 性质：对 `04_专利目标冻结_…` 执行框架的修订与澄清。不改变：R5 七条启动条件、intake gate 五步、R5 = NOT STARTED 状态、core-patent = NO-GO 状态、两源不相加规则、V2.0 全部术语红线。
> 触发：CORE-SEARCH R1–R4 + RD-1/RD-2 的经验表明，冻结的核心闭环（站级触发→边界变化→责任识别→重分配→反馈更新）天然要求同源真实闭环日志，公开数据几乎必然缺环；若把"完整实测链"当作发明设计的启动条件，项目将无限等待。

## 1. 核心纠偏（冻结）

**"有真实数据证明"与"能否设计/撰写核心专利"是两个问题。**

- 专利授权要件：技术问题具体、手段可实施（enablement）、设备作用关系明确、技术效果具有合理工程因果、权利要求与现有技术拉开距离——**均不以公开数据集复现为前提**。
- 真实数据的角色 = **验证与收敛工具**（分环节验证、淘汰不成立结构、提供工程量级），不是发明设计的准入证。
- 同时保留 v1 教训的原始边界：**禁止在无验证证据时输出收益/效果量化结论**。v1 的错误是"合成数据自证收益"；本修订允许设计机制，但不允许用设计文档宣称收益。

## 2. R5 角色重定义（澄清，不改标准）

```text
R5 七条启动条件 / intake gate 5 步      = 不变（字面冻结）
R5 的角色：真实部署问题与效果证据升级门  = 核心专利证据等级升级时才需要 7/7
R5 不是：发明设计启动门                  = PD 轨不因 R5 = NOT STARTED 而停摆
```


## 4. 数据问句重定义（取代 04 文件 §6 的单一问句）

04 文件问句"该数据源能否证明设备能力边界变化且足以改变站级控制决策"**保留**，但只用于 A 轨证据准入。PD 轨对数据的问句改为：

> **它能验证发明机制（07 文件 M1–M6）中的哪一个环节、以何种精度？**

既有数据的分环节验证映射随 07 文件 §7 冻结；任何环节未经验证时，对应表述保持"可实施性"级别，禁止升级为效果结论。
