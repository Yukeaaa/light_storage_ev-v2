## 1. 审计方法（8 门）

```
G1 真实性/来源  → G2 场景匹配  → G3 字段覆盖  → G4 字段语义
→ G5 时间粒度   → G6 关键事件存在 → G7 控制因果链 → G8 实验用途/外推边界
```

**门间关系**（本轮实际使用）：
- **G3/G4 必须实测**——字段名存在不代表语义可解；本轮在 SOFIE 上实测到一处 `TEXT` 类型陷阱（见 §2.5）。
- **G5 是硬门**——分辨率不足会直接判死某些用途（15 min 数据无法区分"暂态 vs 持续受限"）。
- **G6/G7 是价值分水岭**——有事件 ≠ 有控制因果；本轮 SOFIE 的 G7 判 CONDITIONAL 即因"限值存在但未观测到咬合"。
- **G8 约束外推边界**——同一源可用于"证明问题存在"，不可用于"证明控制机制有效"。

### 2.5 ⚠️ G4 陷阱：`connector_meter_value.value` 是 **TEXT**

实测 `typeof`：

```
connector_meter_value.value : text = 1,907,665   ← 全部为 TEXT
scn_values.SCN_L1           : real = 537,271
scn_values.max_L1           : integer = 537,271
logging.p_actual            : null = 1,719,844 / real = 1,887,587
```

**后果**：`MIN/MAX/AVG(connector_meter_value.value)` 会走**字典序**，得出 `avg(1669.0) > max(986.8)` 这类矛盾结果（本轮首次分析即踩中，已修正为 `CAST(... AS REAL)`）。**任何使用该表的分析必须先 CAST。**

另注：`logging.p_actual` 有 **1,719,844 行为 NULL（约 47.7%）**——null 与零值必须区分，否则会把"缺测"当作"零出力"。

### 2.7 ⚠️ G7：控制因果链 —— **CONDITIONAL（本报告最重要的一处诚实标注）**

`scn_values` 提供 `max_L1/L2/L3`（各相**最大允许电流**，整数安培）与 `SCN_L1/L2/L3`（实测电流），构成形式上的"约束 vs 实际"对。但实测揭示：

**（a）限值确为活信号，不是常量：**
- `max_L1` 仅 **30 种取值**（0, 14…42），呈**离散步进**；
- `max_L1` **变化 4,126 次**（变化率 0.77%）；非零变化幅度 46 种，主体为 ±1…±6 A，最大 Δ39 A。

**（b）限值受储能状态驱动（60 s 分箱相关，实测）：**

| 关系 | r | n |
|---|---:|---:|
| 限值和 ~ **bat_soc** | **0.732** | 274,649 |
| 限值和 ~ solar_ext | 0.304 | 274,649 |
| 限值和 ~ p_actual | 0.263 | 156,840 |
| 限值和 ~ bat_cur | 0.013 | 274,649 |
| 实际电流和 ~ p_actual | 0.770 | 156,840 |
| 实际电流和 ~ solar_ext | 0.516 | 274,649 |
| 实际电流和 ~ bat_soc | −0.018 | 274,649 |

→ **限值主要由 SOC 驱动**（SOC 高 → 允许电流大；SOC 20–29 档限值三相和 = 0），符合"储能接近满/空时限制充电电流"的工程直觉。**这是一条可解释的物理链。**

**（c）但——未观测到"限值咬住实际"的事件：**

| 实际/限值比 | 占比 |
|---|---:|
| ≤50% | **90.77%** |
| 50–80% | 6.62% |
| 80–95% | 2.07% |
| 95–100% | 0.52% |
| >100% | **0.03%** |

按小时看的典型形态（实测）：

| 时段 | 限值三相和均值 | 实际三相和均值 |
|---|---:|---:|
| 00 时 | 80.5 A | **1.36 A** |
| 03–04 时 | 58.8–59.2 A | 0.32–0.46 A |
| 11 时 | 79.2 A | **23.93 A**（全天峰） |
| 20 时 | 82.1 A | 4.09 A |

→ **限值长期远高于实际电流**：夜间限值 80 A 而实际仅 1.4 A；正午实际峰值仅约 24 A，仍未触及限值。**本切片内未观测到"限值成为紧约束、实际被裁剪"的事件。**

**G7 判定**：

> **SOFIE = REAL CO-LOCATED DATA，控制因果链 CONDITIONAL。**
> 具备：① 约束信号（`max_L`）② 实测响应（`SCN_L` / 逐桩功率）③ 事务级原因真值（`event_actor`/`stop_reason`）④ 事件级异常（Faulted/错误码）。
> 缺口：**缺少"要求 → 被限值裁剪 → 实际"的直接因果证据**——因为在本窗口内限值始终宽松。**若要用 SOFIE 验证"约束导致行为改变"，必须先搜寻限值咬合窗口（SOC 高/低 + 高并发 + 低光照的交叉时段），或确认 2.79 GB JSON 版本是否含更长的历史（README 称三年）。**

**另：SOFIE 不含独立的 EMS `setpoint` / `command` 表**——`max_L` 是 OCPP Smart Charging 的 **ChargeProfile 侧限值**，不是逐次下发的功率指令。**故"`P_requested → P_accepted → P_actual`"三段链目前只能给到 `max_L → SCN_L` 两段。**

### 2.8 G8：用途与外推边界

| 用途 | 判定 |
|---|---|
| PV → BESS → EV 真实时间耦合行为分析 | ✅ 可做 |
| 逐桩"要求 vs 实际"偏差提取（A-EV 线） | ✅ 可做（有逐桩功率 + 5 s/9 s 粒度） |
| "限值/约束 → 响应"因果验证 | ⚠️ CONDITIONAL（需先找到咬合窗口） |
| EV 到达/并发对储能的冲击 | ✅ 可做（944 start / 963 stop + SOC） |
| 季节性 PV–EV mismatch | ✅ 可做（12 月 p_actual 累计 399,975 → 6 月 945,590；SOC 均值 43.2 → 84.0） |
| 当作"真实 EMS 闭环控制数据"使用 | ❌ **不可**（无命令链） |

### 2.9 数据质量哨兵（实测）

| 检查 | 结果 |
|---|---|
| `SBHS_2_bat_soc` 越界（<−1 或 >100） | **4 行**（`max = 4,294,970,000`，明显是类型溢出/坏值） |
| `SBHS_1_bat_soc` / `bat_soc` 越界 | 0 |

| G7 控制因果 | ❌ | **无 EMS 命令；仿真不含现场控制闭环** |
| G8 边界 | — | 见下 |

**正确定位**：
```
CALIBRATED SIMULATION → stress / external validation
```
适合：`建筑类型 × 气候区 × EV 渗透率 × PV/BESS 配置` 的**规模化泛化与压力测试**——**回答"机制是否只在某一个负荷轮廓上有效"**。
**不适合**：problem-existence evidence（不是现场记录）。

> 含 `in.electric_vehicle` / `in.has_pv` / `in.pv_system_size` 三个属性，**对"新增电气化负荷 × 容量约束"类实验的因子设计非常友好**。

## 5. EIPA（Zenodo 21414976）—— **占用率群体证据，用途极窄**

### 5.1 元数据（实测 API + README 全文）

| 项 | 值 |
|---|---|
| 标题 | EIPA charging-point occupancy dataset: a 14-day full-population reference series with source-cadence characterisation (Poland, June–July 2026) |
| 版本 / 发布 / 许可 | v1.0.0 / 2026-08-05 / **CC BY 4.0**（代码 MIT） |
| 采集窗口 | **2026-06-23 14:43 → 2026-07-07 14:43 UTC**（14 天） |
| 轮询节拍 | **60 s**（经验确定的原生发布节拍） |
| 完整率 | 20,156 次计划轮询、1 次失败 → **99.97%**，最长 gap 3 min |
| 记录方式 | **变更触发式 delta logging**（仅当状态码或源侧时间戳变化才落行） |

### 5.2 字段（实测）

**`transitions.csv.gz`（7,230,030 行、27,666 个 distinct point_id）：**
```
ts_utc, point_id, status, status_ts
status: 0 = unavailable, 1 = free, 2 = busy
```
> **关键**：7,230,030 行中**仅 905,427 行是真实状态变化**，其余为"仅源侧时间戳移动"。**误把总行数当事件数会高估约 8 倍。**

**`points_meta.csv.gz`（13,928 行）：** `point_id, station_id, max_power[kW], interfaces, modes`；分析 cohort **13,168 点（7,499 AC + 5,669 DC）**。

**`poll_log.csv.gz`（21,239 行）** / **`calib.csv.gz`（1,083 行）**：逐轮审计与节拍标定。

### 5.3 ⚠️ 一处用户未提到的硬警告：`status_ts` 长尾

README 明写（**实测复读原文**）：
> 在分析 cohort 内，**1.50% 的状态变化其时间戳老于一小时**，**最极端回溯达 113.2 天**；源时间戳与观测时刻的**中位滞后 86 s**（IQR 69–105 s），无负值。

**后果**：若用 `status_ts` 重定事件时刻，必须**先刻画这条长尾**；直接使用会把陈年旧时间戳当作当下事件。

### 5.4 判定

| 门 | 判定 |
|---|---|
| G1 真实 | ✅（波兰国家替代燃料基础设施登记册 UDT/EIPA） |
| G2 场景 | ★★★（充电设施占用，非能源系统） |
| G3 字段 | ★★（仅状态码 + 静态功率/接口） |
| G4 语义 | ✅（三态码定义清楚） |
| G5 粒度 | **60 s**（原生） |
| G6 事件 | ★★★★★（720 万行状态变更） |
| G7 控制因果 | ❌ **无 P_actual / SOC / P_command / EV energy request** |
| G8 边界 | — |

**正确定位**：
```
INFRASTRUCTURE POPULATION EVIDENCE
```
适合：占用率、可用率、故障/不可用持续时长、时段规律、功率等级与使用规律；**可用于攻击"充电设施可用性是重大系统问题"类候选**（unavailable 到底多频繁、多长、多少点同时发生）。

**红线**：
> **绝对不能从 EIPA 的 free/busy/unavailable 推导柔性功率。** 不得说"某桩 busy，因此有 XX kW 可调"——这是典型的"状态字段 → 物理能力"越级推断。

## 7. 对 3-a（P0 拆解）的输入

数据审计后确认："配电容量受限 × 新增负荷"**不能只拆成一个问题**。已识别的 8 个候选技术矛盾（**仍是问题拆分假设，不是专利候选**）：

1. 规划接入容量与运行实际容量不一致；
2. 新增 EV/生产负荷服务保证与容量约束冲突；
3. 储能功率够、但能量持续性不够导致的接入虚高；
4. PV/BESS/EV 共同存在时，静态 hosting capacity 失真；
5. 正常日可承载，但极端日/连续低光照/高并发时服务失效；
6. 有功容量尚有余量，但电压/无功/谐波/相不平衡先成为瓶颈；
7. 为保证最坏情况而过度扩容，与允许受控降级之间的矛盾；
8. 配网给出的外部容量边界，与园区内部不可中断/可延迟负荷的一致分解。

**逐个追问**：`这个问题到底普不普遍？ → 商用系统已经怎么做？ → 最强现有方案是什么？ → 还剩什么不是普通 MPC/MILP？`

**SOFIE 的直接贡献**：其为矛盾 3/4/5 提供了现实锚点——`max_L` 受 SOC 驱动（r=0.73）、SOC 高时放开、12 月 SOC 均值 43.2 而 6 月 84.0，且 12 月 p_actual 累计仅为 6 月的 42%。**"季节/储能状态决定可承载 EV 负荷"在真实共址系统中有可观测痕迹。**
