## 1. 两条必要技术特征链（并排钉死）

**A —— 能力修正链（"能做多少"）**

```text
execution evidence           获取功率控制要求 + 对应实际执行结果
        ↓
attribution                  有效性与能力归因判断（排除通信无效 / 暂态响应偏差）
        ↓
directional capability       方向化可用能力状态（成对方向边界，可带可信度）
        ↓
resource takeover            站级功率缺口 → 可承接贡献重算 → 跨资源定向转移
        ↓
capability update            依实际执行结果回写能力状态或其可信度
```

**C —— 资格门控链（"能否参与、能参与什么"）**

```text
operating / abnormal obs     运行状态信息 + 异常指示信息
        ↓
control qualification        三级有序离散资格 + 第三等级双子状态（仅观测 / 完全阻止）
        ↓
allowed action scope         等级 → 允许控制动作范围（完整 / 受限非空 / 空）
        ↓
resource admission           等级 → 是否纳入可控资源集合（完整子集 / 受限子集 / 均不纳入）
        ↓
qualification recovery       满足恢复判据 → 等级提升 + 动作范围与准入条件重开
```

**一句话关系**：C 回答"**这台设备算不算可调度资源、被允许做什么动作**"；A 回答"**已被调度的资源实际做了多少、缺口转给谁、能转多少**"。

## 2. 必要技术特征隔离表（逐维对照）

| 维度 | A 必要技术特征 | C 必要技术特征 | 隔离判定 |
|---|---|---|---|
| **主输入** | 功率控制要求 **+ 对应实际执行结果**（指令—执行**成对**） | 运行状态信息 + 异常指示信息（设备**自身状态观测**） | **不重叠**。A 的输入是"要它做多少 vs 实际做了多少"；C 的输入与"是否下达过指令、下达了多少"完全无关 |
| **中间状态对象** | 方向化可用能力状态（成对方向边界，可带可信度） | 控制参与资格（三级有序离散等级 + 双子状态） | **不重叠**。语义 = "能做多少" vs "可否参与"；性质 = 连续 vs 离散有序 |
| **核心判定** | 有效性与能力归因判断：偏差**是否构成**能力受限的**证据** | 依据运行/异常信息确定**资格等级** | **不重叠**。A 判"偏差能不能算能力证据"；C 判"设备处于哪个资格等级" |
| **第一控制后果（数值/动作级）** | 站级功率缺口 → 可承接贡献重算 → 承接资源及其**功率修正量** | **允许控制动作范围**（完整 / 受限非空 / 空） | **不重叠**。A 产出**数值修正量**；C 产出**动作权限集合** |
| **第二控制后果（集合/结构级）** | 跨设备**定向转移**（把缺口从受限资源转给承接资源） | 是否纳入**可控资源集合**（完整子集 / 受限子集 / 均不纳入） | **需显式区分——见 §4.2**。二者都涉及"资源"，但 A 在**已参与调度的资源之间**分配，C 决定**某设备是否算作可调度资源** |
| **闭环回写** | 依功率修正后的实际执行结果更新**能力状态或其可信度** | 满足恢复判据 → **等级提升** + 动作范围与准入条件重开 | **不重叠**。A 回写**能力知识**；C 回写**资格等级** |
| **触发源** | 执行偏差（指令 vs 实际） | 设备运行 / 异常观测变化 | **不重叠** |
| **状态空间性质** | 连续（边界数值 + 可信度） | 离散有序（三级）+ 第三等级双子状态 | **不重叠** |

**结论**：八个维度上两案必要技术特征**无一项构成对方的必要前提**。唯一需要额外写清的是"资源"与"通信"两处**事实上的输入域重叠**（§4）。

## 4. 边界易混点（本协调文档识别出的最高风险）

### 4.1 「通信」在两案中的角色不同 —— **最高风险边界**

两案都要用到通信状态，这是**事实上的共同输入域**。但技术意义与后果**完全不同**：

| | A【b】 | C 权 1【a】+ 权 6/D3 |
|---|---|---|
| 作用对象 | **偏差**（指令 vs 实际之差） | **设备状态**（异常指示信息） |
| 逻辑动作 | **排除**（通信无效对应的偏差**不进入**能力证据） | **降级**（通信异常**指示**是资格降级的输入） |
| 目的 | 防止把通信问题**误判为能力不足** | 决定设备**是否仍可被控制** |
| 后果 | **不更新**能力状态 | **等级下降**（可及资源集合收缩） |
| 一句话 | 「这种偏差**不算**能力证据」 | 「这种状态**使设备失去**资格」 |

**写法要求**：
- A 案在【b】处定义"通信无效偏差"时，**不得**写成"通信异常导致资格下降"；
- C 案在【a】处定义"异常指示信息"时，**不得**写成"依据执行偏差判定异常"。

**判定**：两案的通信用法**可索引**（前者做减法、后者做降级），但**必须在各自说明书中给出各自定义位**，否则极易被审查员视为同一技术手段的两种表述，进而引发互吞或双案实质同一的攻击。

### 4.2 「资源」在两案中的角色不同

| | A【d】 | C 权 1【d】/ 权 5 |
|---|---|---|
| 问题 | "在**已被调度**的资源中，谁还能多接一点" | "某设备**是否进入**可调度范围" |
| 前提 | 这些资源**已经在**可调度范围内 | **无前提** |
| 层次 | **分配层** | **准入层** |

- 逻辑顺序上 C 在 A 之前，**但两案独立权都不得要求对方存在**：
  - A 的【d】必须写成"从**多个可控资源**中选择承接资源"（**不写**"从具备资格的资源中"）
  - C 的【d】必须写成"确定是否纳入**参与调度的可控资源集合**"（**不写**"依据其可用能力"）
- 只有到 §6.3 的组合实施例（③ 层）才写"C 先过滤、A 后分配"。

### 4.3 「运行」一词的两种用法

| 案 | 用语 | 含义 |
|---|---|---|
| A【d】 | **运行约束** | 分配时的物理/安全边界（SOC、温度、额定限值、控制模式、爬坡率……），定义位在 A 说明书 |
| C 权 1【a】 | **运行状态信息** | 设备当下处于何种**运行状态**（在运 / 停机 / 检修） |

**写法要求**：两案说明书首次出现处各自加限定语（A 用"运行约束"，C 用"运行状态信息"），**不做同义替换、不互相引用**。

## 5. 三层材料划分

### 5.1 ① 两案独占段

| 案 | 独占内容 | 落位 |
|---|---|---|
| **A** | 偏差归因判定（含通信无效/暂态响应排除）、方向化可用能力状态维护、站级功率缺口与可承接贡献重算、跨资源定向转移与功率修正量确定、执行反馈回写 | A 说明书"发明内容"+"具体实施方式"主体；A 独立权与从属梯 |
| **C** | 运行/异常信息 → 三级资格（含第三等级双子状态）、等级 → 允许控制动作范围、等级 → 控制资源子集准入、恢复判据与权限重新开放、渐进恢复顺序 | C 说明书"发明内容"+"具体实施方式"主体；C 独立权与从属梯 |

**纪律**：独占段**不得**出现对方的状态对象名（检查表见 §7）。

### 5.2 ② 可共享基础设施段

| 共享项 | 两案为何都要 | 共享写法约束 |
|---|---|---|
| 设备通信接口与协议（IEC 61850 / Modbus / 厂商私有） | 都要从设备取数据 | **必须写成"可采用本领域常规的……"**，不赋予创造性 |
| 遥测采集与时戳对齐 | 两案输入都需时间对齐 | 同上 |
| 数据质量检查（缺测 / 跳变 / 延迟标记） | 两案都用 | 同上。**注意**：共享的是"检查动作"，**不共享"检查结果的技术用途"**——C 中数据质量标记是**资格降级的输入之一**（权 6/D3），A 中则服务于**偏差有效性判定** |
| EMS / 站级控制器 / 边缘控制器 | 两案的执行主体 | 只做硬件/软件载体描述 |
| 可控设备接口（PV / BESS / EV / 充电设备） | 两案的受控对象类型 | 只共享"**设备类型清单**"；**不共享"各类型的映射规则"**（A 的等效调节余量映射、C 的等级映射各自独占） |

**共享段总纪律**：共享段只能出现在说明书的**背景技术**与**具体实施方式的常规实现描述**中，且必须以"可采用本领域常规……"表述。**任何共享段内容都不得进入任一案的独立权。** 共享段的目的是让两案说明书**互相读起来不矛盾**，而不是建立依赖。

### 5.3 ③ 可选组合实施例

**写法模板（两案应采用实质一致、各自段落独立完整的表述）**：

> 可选地，在另一实施例中，上述站级功率控制可与设备控制参与资格判定相结合：先根据目标设备的运行状态信息与异常指示信息确定其控制参与资格，将不满足参与条件的设备排除于参与调度的可控资源集合之外；再对参与调度的设备执行上述执行偏差归因与方向化可用能力状态的更新，并据此确定站级功率缺口与承接资源。

**双输入示意**：

```text
                        ┌─ C: 控制参与资格 ────────→ 谁可被调度（准入层）
站级调度输入 ───────────┤
                        └─ A: 能力状态 / 可承接贡献 → 谁能承担多少（分配层）
```

**四条红线**：

1. 必须以「**可选地 / 在另一实施例中 / 进一步地**」引入；
2. **不得写入任一案的独立权**；
3. **不得写成互为必要特征**——反向依赖（如"若资格为第一等级则执行上述归因"）同样**禁止**进入独立权；
4. **组合实施例不得用于独立性论证**（不能因组合有效而声称单案不完整，也不能因单案已完整而否认组合价值）。
