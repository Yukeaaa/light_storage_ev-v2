# A-B-C-F 横向组合与专利组合架构评审 V1

**版本**：V1（2026-09-09）
**性质**：PD 轨横向架构评审；不扩文献检索面、不做新实验、不改权利要求语言
**依据**：A/B/C/F 各候选 knockout 文档 + 定向深挖报告 + C-OpenCEM 验证报告 + 07 号机制拆解 + 12 号反审
**目标回答**：四个候选是四件独立专利，还是一个主干系统里的不同层？哪些应独立申请，哪些适合改进/组合/防御？

## 阶段 1：保护对象去重

### 1.1 各候选状态对象钉死

| 候选 | 保护的状态对象 | 物理语义 | 更新触发 | 输出消费者 |
|------|--------------|---------|---------|-----------|
| **A** | `directional_capability_state` — 方向化可用能力状态（成对边界 B↑/B↓） | "这台设备在当前条件下**能输出/吸收多少功率**" | 执行偏差 + 归因判定 | 站级缺口计算、跨资源承接 |
| **B** | `station_flexibility_envelope` — 站级时变灵活性包络 | "全站在给定时间尺度和持续时长内**一共能调多少**（含方向）" | 各资源能力输入 + 承诺扣除 + 公共约束裁剪 | 上级调度接口、任务分解、实时修正 |
| **C** | `control_qualification` — 控制参与资格等级 {FULL/LIMITED/OBSERVE/BLOCKED} | "这台设备**是否被允许参与控制**、允许到什么程度" | 通信/告警/运行状态/数据新鲜度 | 资源池门控、功率分配器输入过滤 |
| **F** | `physical_verdict` + `authorization_state` + `execution_state` — 三层安全状态链 | "这次 Agent 生成的控制动作**物理可行吗**、**被授权执行吗**、**实际执行成功了吗**" | Agent 候选动作 → verifier → auth gate → EMS 回传 | 人工介入、回退/降级策略、审计 |

### 1.2 语义可区分性判断

**A vs B：可区分，但需警惕推导关系**
- A 是设备级能力知识（"我有多少"），B 是站级聚合包络（"我们一共能交付多少"）
- 风险：如果 B 的聚合输入只是"把各设备能力加起来"，审查员会说 B 是 A 的平凡延伸。**B 必须证明聚合不是简单求和**——B2（持续时长-能量耦合）和 B5（承诺后剩余）是 B 的独立增量：A 不关心"能维持多久"，不关心"已承诺多少还剩多少"
- 判定：**可区分**，前提 B 独立权不以"A 修正后的能力作为必要输入"

**A vs C：可区分，正交性强**
- A 关心"能多少"，C 关心"该不该参与"。一台设备可能 FULL 资格但能力收缩到很小（A 的 B↑已收缩），也可能 BLOCKED 资格但额定能力很大
- 判定：**可区分，低碰撞风险**

**F vs A/B/C：可区分，层级的本质不同**
- F 的对象是一次控制动作的三层安全状态，不持续维护设备属性
- F 的 `physical_verdict` 是 pass/fail 判定，不是能力数值；`authorization_state` 是动作级授权，不是设备级资格
- 判定：**可区分**

**C vs F 的模糊区（需要警惕）**
- C 的 `control_qualification ∈ {FULL/LIMITED/OBSERVE/BLOCKED}` 和 F 的 `authorization_state ∈ {AUTO/HUMAN-APPROVAL/REJECT}` 形态相似
- 关键区别：C 是**设备持久属性**（这台设备当前能不能被控制），F5 是**动作瞬时判定**（这次动作能不能执行）
- 风险：如果 F5 的授权逻辑写成"检查设备资格状态，BLOCKED 则 REJECT"，F5 退化为 C 的调用方，F 的创造性被 C 吞噬
- 判定：**可区分，但 F5 的独立权必须包含除 C 资格之外的独立判定维度**（风险等级、动作类型、操作者/Agent 权限）

### 1.3 结论

四个状态对象语义可区分，不存在一个可以从另一个直接推导的关系。不存在术语换皮风险，但 C→F5 的连接需要特别注意 F5 不被简化为 C 的 pass-through。

## 阶段 2：接口关系图

### 2.1 五条连接逐一审查

#### 连接 1：C → B（资格门控 → 灵活性聚合）

| 维度 | 分析 |
|------|------|
| 接口方向 | C 的 `control_qualification` → B 的资源池过滤 |
| 数据契约 | B 聚合时只纳入 FULL/LIMITED 设备，OBSERVE/BLOCKED 排除 |
| 独立性 | **B 去掉 C 仍能独立成立**——B 可以假设"所有参与聚合的设备当前具备控制条件" |
| 组合价值 | **中等**——"只有具备控制资格的设备的灵活性才计入站级包络"是合理的工程约束，但区别性不强。**除非 C 的 LIMITED 状态在 B 中映射为"只聚合保守方向的能力"**，否则这个连接的区别价值不足 |

判定：组合有价值但不足以支撑独立组合权利要求。适合作为 B 的从属权项或说明书实施例。

#### 连接 2：A → B（修正能力 → 灵活性聚合）

| 维度 | 分析 |
|------|------|
| 接口方向 | A 的 `directional_capability_state` → B 的 B1 单资源方向化可调能力 |
| 数据契约 | B 聚合时用 A 修正后的 (B↑^cap, B↓^cap) 替代额定功率 |
| 独立性 | **B 去掉 A 仍能成立**——B 的输入可以是额定能力、预测出力、SOC 约束能力等任意能力估计 |
| 组合价值 | **高**——"用执行证据修正后的方向化能力而非额定/预测能力构建站级包络"是实质区别。lit_id 9 和 lit_id 12 都用的是静态/单向能力 |
| 风险 | **A 可能被 B 稀释**——如果 B 的独立权把"A 修正后的能力"写成普通输入之一（不强调修正机制），A 的创造性被 B 吸收 |

判定：组合价值高，适合在 B 的从属权中引用 A 作为能力修正源，但 B 独立权中能力输入保持上位（"各资源的当前可用能力估计"）。

#### 连接 3：C → F（设备资格 → 授权门）

| 维度 | 分析 |
|------|------|
| 接口方向 | C 的 `control_qualification` → F5 `authorization_state` 的输入之一 |
| 数据契约 | F5 在判定授权时查询 C 的输出：QUALIFICATION=BLOCKED → 强制 REJECT |
| 独立性 | **F 去掉 C 仍能成立**——F5 的授权判定本身包含多维度（风险等级、动作类型、Agent 权限），C 只是其中一个维度 |
| 组合价值 | **中等偏低**——"BLOCKED 设备不接受 Agent 下发的控制指令"是工程常识。不会导致 C 被 F5 吞掉，因为 C 的创造性在状态机的完整性（离散等级 + 门控 + 恢复） |
| 风险 | 如果 F5 独立权把 C 的资格作为必要输入，F 会依赖 C |

判定：适合在 F 的从属权或说明书中提及。F5 独立权中授权判定维度保持上位（"设备运行状态约束"），不绑定 C 的具体状态名。

#### 连接 4：B → F（灵活性包络 → 物理校验）

| 维度 | 分析 |
|------|------|
| 接口方向 | B 的 `station_flexibility_envelope` → F4 物理校验器的约束集 |
| 数据契约 | F4 校验候选动作时增加约束：候选动作必须在站级灵活性包络内 |
| 独立性 | **F 去掉 B 仍能成立**——F4 的物理校验器可以用设备级约束（SOC/温度/爬坡/PCC 限值）直接校验 |
| 组合价值 | **中等**——比"校验是否违反单设备约束"更精确，但 lit75 已有"安全校验 Agent"，审查员可能认为增加聚合层约束是显然的 |

判定：价值适中，不建议写入任何独立权。适合在 B 或 F 的说明书中作为协同实施例。

#### 连接 5：A → F（能力修正 → 执行回退）

| 维度 | 分析 |
|------|------|
| 接口方向 | F6 执行失败 → 触发 A 的 M2/M3 边界收缩 |
| 数据契约 | F6 检测到 execution_state=FAILED → 向 A 上报执行偏差事件 → A 的 M2 归因判定 → 可能触发 M3 边界收缩 |
| 独立性 | 双向独立：A 的闭环不依赖 F6（A 用 M1 直接检测偏差），F6 的回退不依赖 A（F6 可自己做降级/保守策略） |
| 组合价值 | **高，但有边界模糊风险**——F6 关注**本次动作的即时安全**（回退/人工接管），A 的 M6 关注**长期能力知识更新**（边界收缩/恢复/置信度） |
| 风险 | **边界模糊风险高**——如果 F6 的 fallback 中包含"收缩该设备的能力边界"，A 的 M6 被 F6 吸收 |

判定：**需要严格边界定义**。F6 的 fallback 只到"本次动作撤销/降级/人工接管"，不包含能力边界修正。A 的 M6 只管长期能力状态更新，不负责即时安全退出。时间尺度分离：F6 是秒级，A-M6 是分钟级。

### 2.2 接口关系总览

```
                C (control_qualification)
               /                            \
              ↓                              ↓
      B (station_flexibility_envelope)     F5 (authorization_state)
              ↑                              ↑
              |            F4 ───────────────┘
             (physical_verdict)
              |                              ↓
      ── B1 能力输入 ── F6 (execution_state)
                             ↓
                      A-M6 (boundary update)
                            ↑
          A (directional_capability_state)
                            ↓
                  M4 (gap) → M5 (transfer)
```

## 阶段 3：独立申请能力

### 3.1 A 候选

- **能否单独申请**：能——五步链自包含：偏差→归因→能力状态→跨资源承接→回写
- **独立权核心**：偏差归因 + 方向化能力状态更新 + 跨资源定向转移 + 执行回写。12 号 v2 草案已验证
- **"缺少 XX 层无法工作"的防御**：缺少 C？→ 说明书中"可选地，先过滤无资格设备"；缺少 B？→ A 的 M5 只做设备到设备的定向转移，不依赖站级包络。A 的输入是"功率控制要求"，来源不限

**结论：A 独立申请能力 = 强**

### 3.2 B 候选

- **能否单独申请**：能——B1→B2→B3→B4→B5 自包含。B 的输入是"各资源当前可用能力"，来源不限（额定/预测/修正后均可）
- **独立权核心**：B2（持续时长-能量耦合）+ B5（承诺后剩余包络）是 B 区别于 lit_id 9/12 的核心。B1+B3（双向+异构映射）是辅助区别
- **"缺少 XX 层无法工作"的防御**：缺少 A？→ B 可以接受任何能力估计作为输入。缺少 C？→ B 假设参与聚合的设备均已就绪

**结论：B 独立申请能力 = 强（B2/B5 全库空白是核心支撑）**

### 3.3 C 候选

- **能否单独申请**：能——C1→C2→C3→C4→C5 完整闭环。OpenCEM 验证报告提供了数据支撑（4 状态自然出现 + 42,671 次恢复事件 + 64,842 次池门控变化）
- **独立权核心**：离散权限等级 + 资格→资源池门控 + 恢复机制。与 lit45 的区别（控制域 vs 信息安全域、离散 vs 连续、有恢复 vs 无恢复）必须写入说明书
- **"缺少 XX 层无法工作"的防御**：不依赖 A/B/F 的任何输入。C 的输入是原始设备状态观测（通信/告警/运行模式），这些在任何站都有

**结论：C 独立申请能力 = 强（数据门槛最低、验证最充分）**

### 3.4 F 候选

- **能否单独申请**：能——F4→F5→F6 三核自包含
- **独立权核心**：独立物理校验器 + 与校验分离的授权门 + 执行失败安全退出。F1/F2/F3 已进入拥挤区，不应写入独立权
- **"缺少 XX 层无法工作"的防御**：缺少 C？→ F5 授权门可以用任何权限/状态约束，不绑定 C 的具体状态。缺少 B？→ F4 校验器直接用设备级约束。缺少 A？→ F6 回退策略是即时安全机制，不依赖能力修正

**结论：F 独立申请能力 = 中等偏强**（F4→F5→F6 独立成立，但 F4 的 Neighbor 很强（lit71/lit75），F5/F6 的精确空白需要更精细的语言才能锁住）

## 阶段 4：组合攻击与自相残杀

### 4.1 外部组合攻击

**攻击 1：lit_id 9（B3+B4）+ lit75（F4/F5 Neighbor）覆盖 B→F 连接**
- lit_id 9 提供"异构资源聚合 + PCC 约束裁剪"，lit75 提供"安全校验 Agent→执行 Agent"
- **威胁评估：中等**——组合后是"聚合能力 + 安全校验后执行"，但缺失 B2（持续时长-能量耦合）、B5（承诺后剩余）、F5 的"可行性 vs 授权分离"
- **防御**：B 独立权中 B2+B5 是 lit_id 9 不覆盖的；F 独立权中 F5/F6 的精确空白是 lit75 的 Neighbor 不覆盖的

**攻击 2：CN122203352A（标量降额）+ lit_id 9（聚合）覆盖 A→B 连接**
- **威胁评估：低**——CN122203352A 无偏差归因、无方向化、无跨设备转移、无执行回写；它只能提供"标量降额后的能力数值"，A 的区别在"怎么修正"而非"修正后的值"
- **防御**：A 独立权中的归因判定（v2 的【b】段）是 CN122203352A 完全没有的

**攻击 3：CN122371331A（偏差回写计划）+ lit75（安全 Agent）覆盖 A→F 连接**
- **威胁评估：低到中等**——CN122371331A 有偏差检测和计划回写，但无方向化能力状态、无跨设备转移；lit75 有安全校验 Agent 但无独立物理校验器与授权门分离
- **防御**：A→F 连接的核心价值不在"有连接"，在"F6 不吞 A-M6"的边界定义

### 4.2 自相残杀风险

**风险 1：A 被 B 稀释（高）**
- 场景：B 的说明书中把 A 的能力修正写为 B1 的"一种能力估计方式"，不提 A 的归因机制
- 后果：A 的"偏差→归因→能力状态更新"变成 B 的普通输入预处理
- **防御**：A 和 B 分开申请，互不引用对方为必要特征。B 的从属权可以写"所述能力估计基于执行偏差的归因修正"，但独立权保持上位

**风险 2：C 被 F5 吞掉（中等）**
- 场景：F5 授权门写为"根据设备控制资格判定授权策略"
- 后果：C 的"资格→门控"变成 F5 的一个判断条件
- **防御**：F5 独立权中授权判定维度上位为"设备运行状态约束"，不引用 C 的状态枚举。C 的创造性在状态机的完整性，F5 的创造性在"可行性与授权分离"

**风险 3：A 和 C 互反引用（低）**
- 场景：A 写"只对有资格的设备修正能力边界"，C 写"能力边界收缩到零时自动 BLOCK 资格"
- 后果：形成循环依赖，审查员可能认为两案实质是同一发明的拆分
- **防御**：A 的 M2 已经有"排除通信无效偏差"的逻辑，不需要引用 C 的资格状态作为前置条件。C 的资格判定基于通信/告警/运行状态，不需要引用 A 的能力边界。**当前设计中不存在互反引用需求**

### 4.3 组合攻击面总结

| 攻击路径 | 涉及候选 | 威胁等级 | 关键防御点 |
|---------|---------|---------|-----------|
| lit9 + lit75 | B→F | 中等 | B2+B5 空白 + F5/F6 精确空白 |
| CN122203352A + lit9 | A→B | 低 | A 的归因判定 |
| CN122371331A + lit75 | A→F | 低-中 | F4→F5 断裂 + A 的方向化 |
| 自相残杀 A→B | A, B | **高** | 独立申请、互不引用为必要特征 |
| 自相残杀 C→F5 | C, F | 中等 | F5 维度上位、不引用 C 状态枚举 |
| 互反引用 A↔C | A, C | 低 | 当前无互反引用需求 |

## 阶段 5：组合架构与申请策略

### 5.1 每条线的定位

| 候选 | 定位 | 理由 |
|------|------|------|
| **A** | **核心专利** | 五步链区别链最完整，12 号 v2 独立权已就绪，文献威胁已逐一核验。M1 有数据验证，M2 RD-2 FAIL 但归因判定机制设计合理，M3-M6 标注 UNVALIDATED 但不影响申请 |
| **C** | **核心专利（同步申请）** | 数据门槛最低、验证最充分（OpenCEM 强 PASS），C4→C5 全库空白，与 A 正交且不碰撞。两件核心专利覆盖"能力修正"和"资格门控"两个正交维度 |
| **B** | **改进专利** | B2/B5 空白清晰，但 B 的价值更多体现在"与 A/C 组合时的系统级覆盖"。作为核心专利的创造性不如 A/C 的链条锐利，但作为从 A/C 延伸的系统级改进有独立价值 |
| **F** | **防御/配套专利** | F4→F5→F6 有空白但 Neighbor 很强（lit71/lit75），且 F 的核心价值（Agent 安全调度）在当前专利组合中处于外围。如果资源有限，F 可以暂缓，先锁定 A+C+B |

### 5.2 建议申请顺序

```
第 1 波（立即）：A（核心）+ C（核心，同步）
  ├─ 两件同日申请，形成交叉引用
  ├─ A 的从属权 2-11 作为 claim ladder
  └─ C 的从属权覆盖资格等级定义、门控映射、恢复逻辑

第 2 波（A/C 受理后 3-6 个月）：B（改进）
  ├─ B 独立权中引用 A/C 作为优选实施例（非必要）
  └─ B 从属权中显式连接 A（能力修正源）和 C（资格门控）

第 3 波（条件触发）：F（防御/配套）
  ├─ 触发条件：大模型电力调度方向检索密度明显上升
  │   （新公开专利 ≥3 篇触及 F4/F5/F6）
  └─ 或：A/C/B 三件获得受理且审查进展顺利，有余力扩展
```

### 5.3 共享层与独立层划分

| 层级 | 内容 | 归属 |
|------|------|------|
| **共享底层** | 设备通信接口、数据采集、时戳对齐、数据质量检查 | 三件共用，不在任何独立权中 |
| **A 独立层** | 偏差归因判定、方向化能力状态维护、跨资源定向转移、执行回写 | A 独占 |
| **C 独立层** | 资格状态机、离散等级映射、资源池门控、恢复逻辑 | C 独占 |
| **B 独立层** | 持续时长-能量耦合、异构方向映射、承诺后剩余包络 | B 独占 |
| **组合层（从属/说明书）** | A→B（修正能力作为 B 的输入源）、C→B（资格门控作为 B 的池过滤）、C→F5（资格作为授权输入之一）、A↔F6（时间尺度分离的边界定义） | 各案从属权或说明书，不写入独立权 |

### 5.4 两件最优组合

如果只能申请两件：

**A + C**

理由：
1. A 覆盖"能力修正 + 跨设备功率重分配"——这是发明本体的核心
2. C 覆盖"控制资格门控 + 恢复"——正交维度，数据验证最充分
3. A+C 组合后，B 的核心价值（聚合包络）可以退化为 A 的 M4/M5 站级视角的延伸，或作为后续改进申请
4. F 在当前检索密度下暂缓，等 F4/F5/F6 方向的新公开增多再决策

次优：**A + B**（覆盖能力修正 + 站级包络，系统级覆盖最广，但 C 的资格门控会被遗漏）

## 评审结论

你的待验证假设得到了验证：

> 它们不是互相竞争，而是分层架构中的不同层。

四层结构（A 能力修正 + C 资格门控 → B 站级聚合 → F 安全编排）在语义上可区分、在接口上可独立、在组合上有增值。建议按 A+C 双核心同步申请 → B 改进跟进 → F 条件触发防御的三波策略执行。

**最关键的设计约束**：
1. A/B 独立权互不引用为必要特征（防自相残杀）
2. F5 独立权中授权判定维度上位，不引用 C 的状态枚举（防 C 被 F5 吞掉）
3. F6 与 A-M6 严格按时间尺度分离：F6=秒级即时安全，A-M6=分钟级能力知识更新（防边界模糊）
