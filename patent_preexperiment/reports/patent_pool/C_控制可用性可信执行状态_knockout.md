## 五问

### ① 这是实际工程里真实存在的动作/矛盾吗？
设备通信断 / 数据陈旧 / 告警 / 限值越限时仍被纳入功率分配，分配给"不可执行"设备。真实工程问题。

### ② 能不能说清设备、数据、状态和控制动作？
- 设备：任意可控设备
- 数据：通信状态 / 寄存器有效 / 遥测新鲜度 / 运行模式 / 告警 / 设定通道 / 测量一致性
- 状态：control-eligible / degraded / observe-only / blocked
- 动作：准入分级 + 分配策略调整

### ③ 有没有至少一种可实施机制？
多维状态 → 准入分级状态机 → 分配策略映射（eligible 全参与；degraded 仅降功率 / 禁提升；observe-only 不参与控制只观察；blocked 禁止）。

### ④ 手头数据/标准/仿真能验证其中哪一部分？
- OpenCEM 寄存器 / 告警 / 状态字段最适合，但寄存器语义未解码 = BLOCKED
- 标准 / 规约可补；门槛低
- 能验：状态字段 → 准入标签的规则一致性（仿真 / 标注）
- 不能验：真实通信故障下控制效果

### ⑤ 现有技术已经做到什么，我们还能在哪个连接点继续做？
"设备可用性"单点可能 crowded；区别压"多维状态融合的准入分级状态机 + 与功率分配联动"。需查重。
