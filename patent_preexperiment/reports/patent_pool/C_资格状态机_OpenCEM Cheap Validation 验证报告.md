# C 候选 OpenCEM Cheap Validation 报告

**版本**：V1（2026-09-08）
**性质**：PD 轨 cheap validation，只回答"OpenCEM 能不能让资格状态机自然跑起来"
**数据**：OpenCEM v1.0.0（Zenodo DOI 10.5281/zenodo.21436223），本地 SQLite 4.44 GB
**脚本**：`C_资格状态机_OpenCEM Cheap Validation 验证报告.md` 同目录下的验证脚本

---

## 1. 结论（先行）

```
C candidate:  PASS（不变）

OpenCEM prototype route:  PASS（强）

判定依据：
  [x] 4 个资格状态（FULL/LIMITED/OBSERVE/BLOCKED）全部自然出现
  [x] 85,674 次状态转换，含双向降级+恢复（BLOCKED↔FULL/LIMITED/OBSERVE）
  [x] 资源池门控产生非平凡变化：32,421 次设备入池/出池事件
  [x] 58 天可控比例 <80%，其中 26 天 <50%（含 2026-05-05 最低 23.6%）
```

**关键限定**：资格判定不依赖 `deroperationstate/deralarmstatus/remotectrlstatus`（三字段全期恒为 0、零转换），而是基于 `outstatus`（3 态）+ `sysalarmflag`（11 模式）+ `chgstatus`（4 态）的联合映射。`derinverterstate` 也几乎全 NULL（仅 890 行有值）。

**这意味着**：
- C 的"控制参与资格"概念在此数据集中成立，但不以"设备运行状态寄存器"为输入，而是以"输出状态 + 告警标志"的组合语义实现。
- 这与实际运行场景一致：小型混合逆变器（Growatt SPI4880）的 `der*` 寄存器可能由本地固件管理，不对外暴露变化，但 `outstatus`/`sysalarmflag` 真实反映设备是否具备控制条件。
- 权利要求中"C1 输入维度"不应限定为 `deroperationstate` 等特定寄存器名，而应抽象为"运行状态观测量 + 告警信号 + 通信/远控确认信号"。

## 3. 资格状态映射（Step 2）

### 3.1 最小规则（无占位阈值，仅按真实枚举映射）

```
BLOCKED:
  sysalarmflag = [8,0,...]   → 紧急告警/故障模式
  sysalarmflag = [64,0,...]  → 保护态
  sysalarmflag = [8192,0,...] → 严重告警
  sysalarmflag = [16,0,...]  → 严重告警
  sysalarmflag = [8192,0,0,16,...] → 多重严重

LIMITED:
  sysalarmflag 非零且不在 BLOCKED 集合中
  主要是 [0,0,0,16,...] 和 [16384,0,...] → 告警存在但可运行

OBSERVE:
  outstatus = 0 → standby/停机，不主动参与
  sysalarmflag = [null] → 语义不确定

FULL:
  outstatus IN (1, 2) AND sysalarmflag = [0,0,0,0,0,0,0,0]
  正常运行 + 无告警
```

**注意**：`chgstatus` 未纳入主规则链。其分布以 0/1 为主（99.999%），2 和 8 各仅极少量行，不具备状态区分力。

### 3.2 资格分布（全局）

| 状态 | 行数 | 占比 |
|------|------|------|
| FULL | 1,741,206 | 77.74% |
| LIMITED | 320,740 | 14.32% |
| BLOCKED | 90,764 | 4.05% |
| OBSERVE | 87,046 | 3.89% |

4 状态全部出现，且没有任一状态占比 >95%。分布非退化。

## 4. 状态转换与恢复（Step 3）

### 4.1 转换矩阵（Top 12）

| 转换 | 次数 | 含义 |
|------|------|------|
| FULL → BLOCKED | 26,550 | 正常运行突降为故障/保护 |
| BLOCKED → FULL | 26,548 | **恢复：故障清除回到正常** |
| FULL → LIMITED | 10,241 | 新告警触发降级 |
| LIMITED → FULL | 10,240 | **恢复：告警清除** |
| OBSERVE → FULL | 4,615 | **恢复：standby 重新并网** |
| FULL → OBSERVE | 4,612 | 正常→停机 |
| LIMITED → OBSERVE | 893 | 告警设备进入 standby |
| OBSERVE → LIMITED | 893 | **恢复：standby 恢复但有告警** |
| LIMITED → BLOCKED | 376 | 告警升级为故障 |
| BLOCKED → LIMITED | 375 | **恢复：故障降为一般告警** |
| BLOCKED → OBSERVE | 167 | 故障设备停机 |
| OBSERVE → BLOCKED | 164 | standby 设备触发故障 |

### 4.2 恢复证据

关键恢复路径汇总：

| 恢复路径 | 次数 | 覆盖 |
|----------|------|------|
| BLOCKED → FULL | 26,548 | 强恢复：故障直接恢复 |
| BLOCKED → LIMITED | 375 | 弱恢复：故障降级为告警 |
| BLOCKED → OBSERVE | 167 | 故障停机（不是恢复但属于状态演化） |
| OBSERVE → FULL | 4,615 | 停机恢复 |
| OBSERVE → LIMITED | 893 | 停机恢复但仍有告警 |
| LIMITED → FULL | 10,240 | 告警清除 |

**总恢复事件**（从非可控→可控）：26,548 + 375 + 4,615 + 893 + 10,240 = **42,671 次**

### 4.3 状态驻留时间

| 状态 | 总 episode 数 | 平均连续快照数 | 最短 | 最长 |
|------|--------------|----------------|------|------|
| FULL | 40,845 | 42.1 | 1 | 29,550 |
| LIMITED | 10,824 | 27.9 | 1 | 2,050 |
| BLOCKED | 27,090 | 3.4 | 1 | 5,050 |
| OBSERVE | 5,558 | 15.3 | 1 | 51,250 |

BLOCKED 平均仅持续 3.4 个快照（约 1.2 分钟），说明告警/故障事件短暂、恢复快。FULL 平均驻留 42 快照（约 18 分钟），是主导状态。OBSERVE 的长尾（最长 51,250 快照 ≈ 36 小时）对应设备较长时间 standby。

### 5.1 门控规则


**关键事件窗口**：

- 2026-01-21：单天 BLOCKED 5,008 次（约 37% 快照被阻塞）

### 5.4 设备级门控差异

Inv1 和 Inv2 的资格分布差异显著（§2.3），导致资源池组成随时间变化——同一时刻两台设备可能在不同资格状态。这直接验证了 C4 的核心命题：**不是所有设备始终参与控制，设备资格是动态的、设备间异质的**。

## 6. Cheap Gate 判定

对照冻结的 gate 标准：

| 标准 | 结果 | 判定 |
|------|------|------|
| ≥2 个资格状态自然出现 + 时间/设备切换 | 4 个状态全部出现，85,674 次转换 | **满足** |
| 降级后恢复可观测 | BLOCKED→FULL 26,548 次 + 总恢复 42,671 次 | **满足（强）** |
| 状态变化改变资源池成员资格 | 64,842 次入池/出池 | **满足** |
| 核心字段不恒定 | `der*` 恒定但 `outstatus`/`sysalarmflag` 变化丰富 | **满足（替代输入）** |
| 枚举语义可解释 | `outstatus` 3 态可映射，`sysalarmflag` 模式可区分 | **满足** |

**综合判定：OpenCEM prototype route = PASS（强）**

C5（恢复资格）获得直接数据支撑：真实数据中存在 42,671 次降级后恢复事件，且恢复后设备重新进入可控资源池。

## 7. 限制与后续

### 7.1 当前限制

1. **`sysalarmflag` 槽位语义未解码**：BLOCKED 判定基于 5 种 `sysalarmflag` 模式的枚举分组，但 slot 0 的值（8/64/8192/16）的实际厂商语义未知。当前分组是基于数据分布的事后切分，不是基于协议文档的先验规则。这不影响"资格变化存在"的结论，但在权利要求中不应引用具体寄存器值。

2. **无外部控制命令**：`ongridactivepowerset` 恒为 0，`remotectrlstatus` 恒为 0。资格状态机的触发是设备自身状态变化（告警、模式切换），不是外部控制指令。C 候选关注的是"控制资格"而非"能力大小"，所以此限制不影响 C 的核心机制验证。

3. **小规模**：仅 2 台 8 kW 实验级逆变器。资格状态的多样性和转换频率在更大规模站点可能不同。

4. **时间缺口**：数据集存在逐日缺口（如 2026-03-15 缺失）。不影响定性结论，但影响精细时间分析。

### 7.2 不需要做的（收口声明）

- 不做闭环控制收益验证（不在本轮 scope）
- 不做 `sysalarmflag` 语义解码（需要厂家协议文档）
- 不做完整调度仿真
- 不把此验证结果用于 A 候选的证据链
