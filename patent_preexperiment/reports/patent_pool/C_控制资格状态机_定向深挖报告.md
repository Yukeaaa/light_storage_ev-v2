# C 候选定向深挖报告：控制资格状态机

**版本**：V1（2026-09-08）
**性质**：PD 轨 cheap-deepening，机制级分析 + 小原型设计
**依据**：08 号 V2.1 矩阵结论 + 五篇目标文献全文

## 1. C 候选链条回顾

```
通信/数据/运行/告警状态 → 控制参与资格 → 权限等级
(full/limited/observe-only/blocked) → 门控资源池与动作 → 恢复资格
```

与 A 候选正交：A 关心"能力多少"，C 关心"该不该参与控制"。

## 2. 五篇目标文献深度提取

### 2.1 lit_id=23（CN116923170A）— 远程检测系统

**披露**：充放子系统（充电/储能/光伏/配电模块）+ 通讯系统 + 远程数据库 + 控制端。监控模块含状态监测 + 远程故障诊断，发现故障报警至控制端。

**C 相关**：
- 有设备状态采集（远程监控基础设施）
- 有故障检测与报警通道
- **缺口**：状态/告警仅用于报警，未形成"此设备是否允许参与功率分配"的判定逻辑。没有权限等级概念，没有资源池门控。

**差距**：C1→C2 断裂。有 C1（通信状态/故障检测），但未进入 C2（资格判定）。

### 2.2 lit_id=27（CN120824740A）— 四可系统

**披露**：云-边-端三层架构。终端自治层采集设备数据、独立处理紧急故障。边缘层做协议转换、生成本地调节指令。云端做全局策略。

**C 相关**：
- "终端自治处理紧急故障"——这是最接近的 C 机制，但触发的是故障切除/保护，不是"资格降级后保留在池中但降低权限"。
- 通信中断时终端启用本地缓存、恢复后补传——涉及通信状态感知。
- **缺口**：自治层故障处理 = 保护性切除，不是控制参与资格分级。没有 "full→limited→blocked" 的概念。

**差距**：C2→C3 断裂。有隐式的"故障→隔离"，但没有权限等级体系。

### 2.3 lit_id=38（CN119628020A）— 能量管理装置

**披露**：本地智能体集群 + 双路传输协调管控 + 高速比较器保护驱动。极简控制器上位调度。

**C 相关**：
- 双路传输（主/备通道）涉及通信可靠性
- 高速比较器 = 硬件级保护，不是控制资格门控
- **缺口**：与 C 链距离远。架构层设计，不涉及"哪些设备允许参与控制"的状态机。

**差距**：仅 C1 层面触及（通信状态感知），其余全断裂。

### 2.4 lit_id=40（CN121965627A）— 台区自治

**披露**：端边台三级自治。端级反射控制（毫秒级）、边缘联邦学习调度、台区级安全多方计算知识共享。三时间尺度调控。

**C 相关**：
- 端级反射控制在通信中断时仍可本地执行——隐式"降级运行"
- 三级自治架构中"通信状态影响控制参与"（矩阵已标注）
- **缺口**：自治是架构特性，不是"资格判定状态机"。没有显式的权限等级、没有资格恢复机制。

**差距**：C2 隐式触及（三级自治隐含不同权限），但没有 C3→C5 的完整链条。

### 2.5 lit_id=45 — 信息能源系统的边缘节点可信评估及控制策略

**披露**（全文可分析，最有价值的 C 邻居）：
- **零信任模型**：默认一切数据不可信、不可用，持续监测、动态调整权限
- **可信度评估**：基于二次性能指标 J(q) 构建可信度触发器 H(q(t))=J(q)−J(q)*，当 H<0 时判定节点不可信
- **可信权重控制器**：c_ij(k+1) 按 c(k)−ω·μ 衰减不可信节点权重，低于阈值 c_ij 时彻底切除
- **事件触发边缘控制**：按信任度调整信息流的动作权重，逐渐降低可疑节点影响

**C 相关**（这是最值得仔细分析的文献）：
- ✓ C1 通信/数据状态：有零信任框架下的数据可信度感知
- ✓ C2 资格判定：H(q(t))<0 → 判定不可信
- ✓ C3 权限等级：权重 c_ij 的连续衰减 → 最终切除（隐式的 limited→blocked）
- ✗ C3 权限等级是**连续权重**而非离散等级（full/limited/observe-only/blocked）
- ✗ C4 门控资源池：权重衰减影响的是信息流，不是功率分配中的可控资源池
- ✗ C5 恢复资格：没有恢复机制，只有衰减-切除方向

**关键区别**：
1. 本文的"可信度"是信息网络安全层面的（防攻击/数据混淆），不是电力设备控制执行层面的（通信断/数据陈旧/告警/限值越限）
2. 衰减对象是信息流权重（邻接矩阵），不是控制参与资格
3. 无恢复机制

**差距**：C1→C3 部分触及，但 C3→C4→C5 断裂。更重要的是"可信度"语义与 C 候选的"控制参与资格"不同域。

## 3. 文献密度评估

| 层次 | 披露文献数 | 说明 |
|------|-----------|------|
| C1 通信/状态感知 | 4+ | 远程监控、故障诊断、协议转换普遍 |
| C2 资格判定 | 0（显式）/ 2（隐式） | lit_id=27 故障切除、lit_id=40 三级自治，但都不是资格判定 |
| C3 权限等级 | 0（离散等级）/ 1（连续权重） | lit_id=45 权重衰减 ≠ 离散权限 |

**结论**：C 链的 C4→C5 是全库空白。C1→C2→C3 有隐式触及但无显式披露。与 A 候选的情况类似——单点 crowded，链式空白。

## 5. 资格状态机小原型设计

### 5.1 状态定义

| 状态 | 含义 | 分配策略映射 |
|------|------|-------------|
| **FULL** | 通信正常、无告警、运行就绪、远程控制使能 | 完整参与功率分配 |
| **LIMITED** | 通信延迟但可接受 / 轻度告警 / 非标准运行模式 | 仅允许执行保守指令（如不增发功率） |
| **OBSERVE** | 通信间歇 / 中度告警 / 运行模式不确定 | 不参与控制，仅采集数据 |
| **BLOCKED** | 通信中断 / 严重告警 / 保护状态 | 禁止控制指令 |

### 5.2 状态转换逻辑（规则级）

```python
# 简化原型：基于 OpenCEM status 字段
def compute_qualification(heartbeat_s: float, alarm_level: int,
                          operation_state: str, remote_ctrl: int,
                          data_consistency: float) -> str:
    # BLOCKED 条件（任一触发）
    if heartbeat_s > 60:          # 心跳超时 60s
        return "BLOCKED"
    if alarm_level >= 3:          # 严重告警
        return "BLOCKED"
    if operation_state in ("FAULT", "PROTECT"):
        return "BLOCKED"
    if remote_ctrl == 0:          # 远程控制关闭
        return "BLOCKED"

    # OBSERVE 条件
    if heartbeat_s > 30:          # 心跳延迟 30-60s
        return "OBSERVE"
    if alarm_level >= 2:          # 中度告警
        return "OBSERVE"
    if data_consistency < 0.5:    # 数据一致性差
        return "OBSERVE"

    # LIMITED 条件
    if heartbeat_s > 10:          # 心跳延迟 10-30s
        return "LIMITED"
    if alarm_level >= 1:          # 轻度告警
        return "LIMITED"

    # FULL
    return "FULL"
```

### 5.3 分配策略映射

| 资格状态 | 充放电功率约束 | 参与目标函数 |
|---------|--------------|-------------|
| FULL | P_min ≤ P ≤ P_max（正常范围） | 完整参与 |
| LIMITED | 0 ≤ P ≤ P_current（仅允许保守操作，不增发） | 参与但不作为主动调节资源 |
| OBSERVE | P = 0（不参与） | 不参与，仅监测 |
| BLOCKED | P = 0（禁止） | 不参与 |

## 6. OpenCEM 验证计划（原型级）

### 6.1 可验证部分
1. **字段覆盖率**：`deroperationstate`, `deralarmstatus`, `remotectrlstatus` 在 OpenCEM 中的 distinct 值分布
2. **状态分布**：用上述规则引擎跑 1 个月数据，统计各状态的时间占比
3. **状态转换频率**：状态转移矩阵（FULL↔LIMITED↔OBSERVE↔BLOCKED）

### 6.2 不可验证部分
- 真实通信故障场景（OpenCEM 数据中 `remotectrlstatus` 全期无变化，`ongridactivepowerset` 恒为 0）
- 资格降级对控制效果的因果影响（需要对比实验）

### 6.3 预期门槛
- 如果 4 个状态字段中有 ≥3 个在 OpenCEM 中有非平凡变化（distinct > 2），则原型可跑通
- 如果状态分布极度偏斜（如 99.9% 时间都是 FULL），则需要用合成扰动或外部数据补充

## 7. 专利空间判断

### 7.1 区别点
1. **控制参与资格 vs 信息安全可信度**：lit_id=45 的"可信度"是网络安全域，C 候选的"资格"是控制执行域
2. **离散权限等级 vs 连续权重**：lit_id=45 用连续权重衰减，C 候选用离散等级映射到分配策略
3. **恢复机制**：全库无 C5 披露，恢复资格是独立区别点
4. **资源池门控**：全库无 C4 披露，资格状态直接驱动可控资源池裁剪

### 7.2 威胁评估
- **弱威胁**：lit_id=27 故障切除（保护逻辑）、lit_id=40 三级自治（架构层面）、lit_id=33 零信任权限（IT安全域）
- **中等威胁**：lit_id=45 可信度衰减（语义不同但形态相似，需在说明书中明确区分"信息安全可信度"与"控制参与资格"）
- **无强威胁**：未发现单篇完整覆盖 C1→C2→C3→C4→C5

### 7.3 判定
**C 候选：DEEPEN / 值得小原型验证**
- 数据门槛低（OpenCEM status 字段可直接映射）
- 与 A 正交，可组合为从属
- 专利空间集中在 C3→C4→C5（离散等级 + 资源池门控 + 恢复）
