## 1. 审计判据（本轮口径）

### 1.1 六个审计维度

| 维度 | A 必须保持 | C 必须保持 | 一票否决信号 |
|---|---|---|---|
| 输入语义 | 通信 / 数据 / 运行信息用于判断"偏差能否作为能力证据" | 通信 / 异常 / 运行信息用于维护控制参与资格 | 两案写成同一个"异常→状态降级"过程 |
| 持久状态对象 | `directional_capability_state`：**能做多少** | `control_qualification`：**是否 / 以何种范围参与** | 一个状态同时承担"能力量 + 准入资格" |
| 资源动作 | 已进入本次控制事务后的承接 / 重分配 | 决定是否进入可调度资源范围 | A 出现"移出可控资源集合"；C 把"按可承接功率分配缺口"作为核心 |
| 反馈闭环 | 执行结果 → 对应资源能力知识更新 | 恢复条件 → 同一资格状态升级 → 权限重开 | C 用执行偏差更新能力边界；A 用异常状态恢复资格 |
| 组合实施例 | 外部参与控制状态仅为可选筛选信息 | 外部能力描述仅为可选调度信息 | 删除组合章节后任一案无法实施 |
| 技术效果 | 减少错误能力归因、形成可承接能力知识 | 避免异常设备参与不适当控制、保留恢复路径 | 两案有益效果写成同一套"提高调度安全性 / 可靠性"空泛效果 |

### 1.2 五个高风险词的审计方法（**不看字面，只看语义**）

对 **通信 / 异常 / 运行 / 资源 / 状态** 逐句追问四问：

```text
这个词在本句中：
① 输入到什么判断？
② 更新什么对象？
③ 产生什么控制后果？
④ 后续反馈又写回什么对象？
```

**共同输入不是问题，共同"技术用途 / 被更新对象 / 控制后果"才是问题。**

### 1.3 审计样本范围

- A：正文 §1–§16（不含附录 A / B）；C：正文 §1–§15（不含附录 A / B）。
- 方法：机器枚举（逐词逐行取证据）+ 人工逐句判定；关键判定记录在 §3、§4。

## 3. 五个高风险词逐句审计

### 3.1 「通信」

| 出处 | 原文摘要 | 四问判定 | 结论 |
|---|---|---|---|
| A §6.1 判据 1 | "数据 / 通信有效性……偏差**不能被采信**时，该偏差不作为能力证据" | 输入到**偏差采信判断**；更新**无**（不更新状态）；后果 = 该偏差不进能力证据 | ✅ A 语义 |
