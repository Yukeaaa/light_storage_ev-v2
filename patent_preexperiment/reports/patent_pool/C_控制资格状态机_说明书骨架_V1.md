## 1. 技术领域

**写作要点**：能源管理系统中的设备控制与功率调度领域；具体涉及**设备控制参与资格的确定、该资格到允许控制动作范围与可控资源集合准入的映射，以及资格恢复**。

- **定义位**：无。
- **红线**：不出现收益、效率、成本类语汇；不出现"状态机"作为权项对应术语。

## 2. 背景技术

### 2.1 现有技术一：设备故障隔离与保护切除

**要点**：既有 EMS／站级控制器普遍采用**二元**处理——设备可用则参与，故障或保护动作则从可控范围中剔除，保护复归后重新纳入。

**不足**：二元处理无法表达"**参与但受限**"；设备一旦出现轻度异常，只能在"完全参与"与"完全剔除"之间选择。

### 2.2 现有技术二：信息侧零信任与可信度评估

**要点**（一类已知机制）：以零信任为前提，持续评估数据/节点的可信度，按可信度**衰减信息流权重**，低于阈值则**切除**该节点在信息网络中的参与度。

> **起草注记**：正式文本中**不得出现内部文献编号**（如 `lit45`、`lit_id 45`）——应按学术引用规范给出**实际文献信息**（作者、题名、出处、年份），或概括表述为"现有技术中已知的一类信息侧可信度评估机制"。区分依据的内部对照见 `C_Claim_v1_lit45_逐限定项反打.md`（不写入正式文本）。

**不足**（**本段是全篇背景技术的关键，必须写足**）：

| 维度 | 该类机制 | 本申请 |
|---|---|---|
| 领域 | 信息安全、数据混淆防护 | 电力控制执行域 |
| 状态空间 | 连续权重 | 离散有序等级 |
| 作用对象 | 信息流权重（影响程度） | 允许控制动作范围 + 可控资源集合准入 |
| 恢复 | 无（仅衰减 → 切除） | 有，恢复判据与权限重新开放联动 |
| 权限表达 | 单一维度（权重高低） | 多维组合子集（类型 / 方向 / 幅度） |

> **必须显式写入一段语义区分**："信息安全域的可信度"表征**信息是否可信**；本申请的"控制参与资格"表征**设备是否被允许参与控制、以及被允许参与何种控制**。二者字面相近而技术意义不同。
>
> **红线**：**不得**把该类机制描述为"同样用于资源准入"或"仅未细化"——那等于自我否定区别。（内部对照：`C_Claim_v1_lit45_逐限定项反打.md` §2.3、§2.4；内部编号不写入正式文本）

### 2.3 现有技术三：分层 / 多时间尺度自治架构

**要点**：端—边—台分层自治、多时间尺度调控等架构级方案，隐含不同层级具备不同控制权限。

**不足**：权限差异停留在**架构层面**，未形成"**状态观测 → 资格判定 → 动作范围 → 资源准入 → 恢复**"的判定链，也无显式的等级与恢复机制。

### 2.4 现有技术不足归纳

1. 参与控制的能力判定为**二元**，无法表达"参与但受限"；
2. 缺乏从**设备状态观测**到**控制参与资格**、再到**动作范围**与**资源准入**的完整判定链；
3. 不可控状态缺乏**中间层次**，导致"要么全用、要么全弃"；
4. 异常解除后缺乏明确的**资格恢复判据与权限重新开放**机制；且若为阻断异常而停止观测，恢复判据将失去信息来源。

> 本节第 4 条**既是对现有技术的评述，也是本申请 [e] 与权 2 子状态设计的引出**——写作时应与 §9、§6 呼应。

## 3. 发明目的 / 要解决的技术问题

**技术问题**（与 §2.4 一一对应）：

1. 如何在设备轻度异常或运行模式不标准时，**使其仍可受限参与**控制，而非二选一；
2. 如何建立**从运行与异常观测到控制参与资格**的判定，并**持续更新**；
3. 如何把资格**映射为可执行的门控**——既约束**动作范围**，又决定**资源集合准入**；
4. 如何在异常解除后**判定资格提升并重新开放权限**，同时**不断开恢复所需的观测来源**。

**发明目的**：提供一种能源管理系统中设备控制参与资格的控制方法及系统，通过**离散有序的资格等级**、**双重控制后果**（动作级 + 集合级）与**带观测保留的恢复机制**，解决上述问题。

- **红线**：发明目的不得写成"提高……效率""提升……收益"。

## 6. 三级资格 + 第三等级双子状态（权 2 / D1）

**骨架映射表（说明书主体表格，建议配图 3）**：

| 等级 | 含义 | 允许控制动作范围 | 资源集合准入 | 观测通道 |
|---|---|---|---|---|
| **第一等级** | 完整参与 | 完整动作集合 | 完整控制资源子集 | 常规遥测 |
| **第二等级** | 受限参与 | 受限非空（类型 / 方向 / 幅度至少一项受限） | 受限控制资源子集 | 常规遥测 |
| **第三等级 · 仅观测子状态** | 不参与控制 | **空** | 不纳入任一子集 | **保留为监测对象**，运行数据参与状态监测 |
| **第三等级 · 完全阻止子状态** | 禁止控制 | **空** | 不纳入任一子集 | **仍获取用于资格恢复判定的运行状态信息与异常指示信息**；运行数据不作为调度控制决策的输入 |

**写作要点**：

1. 必须说明**为何是"三级有序 + 第三等级双子状态"而非四个并列等级**：若把"仅观测"与"完全阻止"写成第三、第四个独立等级，则二者在"**较低等级受进一步限制**"这一有序维度上均为空，**不构成彼此的区别**，与等级体系的有序性相矛盾。
2. 必须说明两个子状态的差异**落在非控制动作维度**（是否保留为监测对象、观测数据用途），而**不在控制动作维度**。
3. 必须说明**两个子状态都保留观测通道**——这是恢复判据的信息来源；若完全阻断观测，异常解除将无从发现，资格无法提升。
4. 技术实现可对应四种设备状态（完整参与 / 受限参与 / 仅观测 / 完全阻止），但**等级骨架为三级**，其中后两者收在第三等级之内。

> **注意**：说明书中可以出现四种状态的中文名与英文缩写；**权利要求侧不得出现**（守 R4）。

## 7. 动作范围映射（权 1【c】、权 3 / D2）

**要点**：

- 三个可组合的限定维度：**控制类型**（允许/排除哪些动作类型）、**控制方向**（单方向 / 双方向）、**控制幅度**（上限、爬坡限制等）。
- 第二等级的允许动作范围**非空**，且相对第一等级**受进一步限制**（至少一种限定）。
- 第三等级的允许动作范围**为空**。
- **必须给出至少两个具体示例**以支撑实施：
  - 示例 A：仅允许单一控制方向的动作（允许放电、禁止充电）；
  - 示例 B：排除特定类型动作（允许有功调节、排除需要快速爬坡的动作）。
- **必须解释**：为何"受限非空"是有意义的工程形态——正是它把本方案与二元剔除区分开（呼应 §2.1 与协调 §4.2）。
- **红线**：不得写成"降低功率"作为第二等级的定义（那是功率数值语义，不是动作权限语义）。

## 8. 可控资源集合准入（权 1【d】、权 5 / D7）

**要点**：

- 定义**两个命名子集**：**完整控制资源子集**（第一等级）、**受限控制资源子集**（第二等级）。
- 第三等级设备**不纳入上述任一子集**。
- **必须写明一句语义澄清**：「**不进入控制资源子集 ≠ 不再观测该设备**」——第三等级设备仍可能作为监测对象保留（仅观测子状态），或保留资格恢复判定所需的观测通道（完全阻止子状态）。
- **必须说明**集合级后果与动作级后果**互不重叠**：集合级回答"是否算作可调度资源"，动作级回答"被允许做什么动作"。

> **定稿期提示**（非本骨架阻塞项）：权 5 现用"包括"为开放式表达，定稿 / 代理阶段可替换为「当控制参与资格为第三等级时，不将所述目标设备纳入所述可控资源集合」或「至少划分为……」以消除"是否还存在第三种未命名子集"的解读空间。见 Claim Draft v1.2 §6 Open item 8。

## 9. 恢复判据与渐进恢复（权 1【e】、权 4 / D5、权 8 / D6）

**要点**：

1. **恢复判据的至少三种实现**（可择一或组合）：
   - 在预设持续时间内**连续**满足恢复条件；
   - 连续多个采样周期满足恢复条件；
   - 恢复阈值**区别于**降级阈值（非对称）。
2. **恢复的后果**：等级由低到高更新，并**重新确定**允许控制动作范围与资源集合准入条件——即**权限重新开放**，而非仅"重新入池"。
3. **渐进恢复顺序**（权 8）：
   ```text
   第二等级
      ↓ 初步恢复条件成立
   仍维持第二等级，试探性开放单一控制方向
      ↓ 该动作的执行满足预设确认条件
   更新为第一等级
      ↓
   开放第一等级的完整控制动作范围
   ```
   **必须说明**：试探性开放发生在**第二等级之内**（即第二等级本已允许的受限动作范围内），因此不与"第一等级 = 完整控制动作"的定义冲突。
4. **必须写明恢复失败的处置**：确认条件不满足时，维持或回退至较低等级，并说明回退不改变观测通道（回到 §6 的双子状态可观测性）。
5. **必须写明**：完全阻止子状态**仍获取**恢复判定所需信息，否则恢复链断裂。

## 10. 实施例 1：独立 C（独立实施）

**目的**：展示本方案**不依赖任何外部能力信息**即可完整实施——这是协调 §6.1 独立性强检验（"删除对方内容后仍可实施"）的说明书体现。

**内容要点**：

- 站点构成：一个站级控制器 / EMS + 若干可控设备（储能、光伏、充电设备中的至少一种）+ 通信链路。
- 数据流：设备上报运行状态信息与异常指示信息 → 资格判定 → 等级映射 → 门控（动作范围 + 资源集合准入）→ 调度器在门控范围内生成控制动作。
- 给出**完整判定示例**：设备 A 正常（第一等级，进完整子集）；设备 B 出现轻度告警（第二等级，进受限子集，仅允许单一方向）；设备 C 通信异常（第三等级，不纳入任一子集，但保留恢复判定所需观测）。
- **必须强调**：整个实施例中，资格的判定输入**只有设备运行状态与异常指示信息**，不需要任何"能力修正""执行偏差"类输入。
