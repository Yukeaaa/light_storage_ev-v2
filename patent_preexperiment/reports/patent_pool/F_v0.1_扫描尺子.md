# F 候选扫描尺子 V0.1

**版本**：V0.1（2026-09-09）
**性质**：PD 轨 cheap-deepening 预注册，只冻结链条结构，不写公式/算法/权利要求
**依据**：13 号方法论转变 + F 候选与 A/B/C/H 的边界定义

---

## 1. 一句话冻结

> **将运行事件或调度要求解析为结构化控制意图，在预设工具权限和参数模式约束下调用确定性电力计算工具形成候选控制动作，由独立物理约束校验器和控制授权门对候选动作进行验证与授权，仅将通过验证和授权的动作下发至能源管理系统，并依据执行确认结果执行完成、回退、降级或人工接管。**

---

## 2. F1–F6 链条定义

### F1：运行事件 → 结构化控制意图

**对象**：从调度要求、告警/运行事件、设备状态、操作员自然语言请求中，解析出可执行的结构化控制意图。

**要求**：输出不是自然语言建议，而是结构化的控制目标，至少包含：
- 控制目标（如降低 PCC 下网功率）
- 作用对象（设备/设备组）
- 时间范围
- 允许/禁止动作类型
- 风险等级或优先级

**典型示例**：
```
目标：降低 PCC 下网功率
对象：BESS_1, EVSE_Group_A
时间范围：未来 15 min
允许动作：BESS 放电 / EV 降充
禁止动作：PV 增发
风险等级：medium
```

**与邻域的区别**：
- "大模型理解告警并生成自然语言建议" → F1-neighbor
- "自动生成调度建议/方案" → F1-neighbor
- 必须输出**结构化**、面向执行的控制意图才计为 F1

### F2：受约束的确定性工具选择与调用（关键节点）

**对象**：LLM 不直接计算潮流或决定设备设定值，而是从**白名单确定性工具**中调用：

```
潮流计算器
优化求解器
设备能力计算器
约束检查器
SOC/能量预算计算器
```

**要求**：工具调用受以下约束（至少体现两种）：
- 工具白名单（只能调用预设工具，不能自由执行代码）
- 参数 schema（调用参数有固定模式）
- 资源权限范围（只能访问/操作特定范围的数据/设备）
- 输入数据版本（工具输入的数据版本可追溯）

**与邻域的区别**：
- "LLM 会调用 API / Python / function calling" → F2-neighbor（通用能力，非电力专用约束）
- "LLM 调用优化算法" → F2-neighbor（无白名单/参数约束）
- 必须明确"LLM 的动作空间被约束到一组确定性、可验证的电力计算工具"才计为 F2

### F3：基于工具结果形成结构化候选动作

**对象**：控制动作由确定性工具的计算结果形成，而非 LLM 自由生成。

**要求**：LLM 负责编排，确定性工具负责计算，结构化动作连接二者：
- 工具返回设备能力、约束条件等计算结果
- 基于工具结果形成具体的设备动作（设定值、方向、持续时间）
- 不是 `prompt → LLM → set_power(100)` 的自由生成

**典型示例**：
```
工具返回：BESS_1 可放电 80 kW, EV_Group_A 可降载 35 kW, PCC 尚需削减 100 kW
候选动作：BESS_1: +70 kW, EV_Group_A: -30 kW, duration: 15 min
```

**与邻域的区别**：
- "LLM 直接生成控制指令" → F3-neighbor（没有工具结果的约束）
- "LLM + 优化算法输出结果" → F3-neighbor（没有明确的结构化动作形成步骤）

### F4：物理安全与运行约束校验（关键节点）

**对象**：**独立于 LLM** 的物理校验器，对候选动作进行安全与约束校验。

**要求**：校验器至少包含以下一种约束检查：
- 设备额定限制
- SOC / 能量约束
- PCC / 变压器约束
- 充电服务约束
- 拓扑/潮流约束
- 控制资格（可与 C 候选组合）

**关键**：校验器必须独立于 LLM（确定性代码/规则引擎），不是"LLM critic agent 审查另一个 agent"。

**与邻域的区别**：
- "LLM 自检/多 Agent 互相评审" → F4-neighbor
- "数字孪生预仿真" → F4-neighbor（仿真验证 ≠ 物理约束校验）
- 必须有**独立于 LLM 的确定性校验**才计为 F4

### F5：控制授权门 → EMS/设备执行（关键节点）

**对象**：安全校验通过 ≠ 自动执行。需要**授权门**决定是否执行。

**要求**：授权逻辑至少基于以下维度：
- 风险等级
- 设备权限
- 指令类型
- 自动执行范围

输出为：AUTO / HUMAN-APPROVAL / REJECT

**关键**：只有通过授权门，才由 EMS 将结构化动作转换成真实控制指令。

**与邻域的区别**：
- "校验通过后直接执行" → F5-neighbor（缺少授权门）
- "AI 给出优化建议供人参考" → F5-neighbor（建议 ≠ 授权执行）
- 必须有**校验与授权分离**才计为 F5

### F6：执行确认 → 拒绝/回退/降级/审计

**对象**：命令下发后的执行确认与失败退出机制。

**要求**：
- 命令已下发 → 接收 ACK / 实测状态
- 判断候选动作是否成功执行
- 成功：结束
- 失败：撤销 / 回退 / 保守策略 / 人工接管

**与 H 边界**：
- F = 在线安全执行工作流（关注如何安全结束或失败退出）
- H = 控制证据链与审计回放（关注长期可验证 provenance/replay 链）
- F6 只保护"在线失败退出"，不吞噬 H 的审计功能

**与邻域的区别**：
- "执行结果回写下一时段计划" → F6-neighbor（滚动优化 ≠ 失败退出）
- "日志记录" → F6-neighbor（记录 ≠ 在线回退动作）

## 3. 扫描矩阵定义

文献对 F1–F6 每个节点的判定：

| 判定 | 含义 |
|------|------|
| A-node（有） | 明确披露该节点的核心机制 |
| Neighbor（邻域） | 触及但不等于该节点 |
| 无 | 未触及 |

**邻域与 A-node 分离**：
- "LLM + RAG" → 全链邻域（知识库检索 ≠ 控制工作流）
- "LLM + 多 Agent" → F4 邻域（Agent 互相评审 ≠ 独立物理校验）
- "LLM + API 调用" → F2 邻域（通用调用 ≠ 确定性电力工具约束）
- "LLM + 优化算法" → F2/F3 邻域（无白名单/参数约束/结构化动作）
- "Agent 互相评审" → F4 邻域（非独立物理校验器）
- "数字孪生预仿真" → F4 邻域（仿真 ≠ 物理约束校验）
- "自动生成调度建议" → F1 邻域（自然语言建议 ≠ 结构化控制意图）

---

## 4. Cheap-knockout 判据

| 组合 | 判定 |
|------|------|
| F2→F3→F4→F5→F6 连续覆盖 | **高风险，F 需重新设计** |
| F1/F2 crowded，但 F4→F5、F5→F6 断裂 | **PASS，继续** |
| 只剩"LLM 调用优化算法" | **HOLD** |
| 确定性工具约束 + 独立物理校验 + 授权门 + 执行失败回退 | **强 PASS** |

---

## 5. 不属于 F 的东西

- **执行偏差归因** → A 链
- **控制参与资格判定** → C 链（可与 F4 组合，但正交）
- **灵活性包络计算** → B 链
- **数字孪生模型偏差** → D 链
- **控制数据证据链/审计回放** → H 链
- **调度目标函数设计** → 背景技术
- **预测模型** → 前提假设
