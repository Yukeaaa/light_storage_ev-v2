## 0. 执行摘要

### V1 废弃原因

V1 `mechanism_matrix.csv` 与 08 号报告（commit `38a4e3a`、`9a10f64`）存在两个 P1 缺陷：

1. **身份键污染**：`batch_ocr_3/4/5.jsonl` 将专利公开号数字部分（如 `114243912`）混用作 `lit_id`，导致同一文献在矩阵中出现两条记录（台账 ID + 公开号）。134 篇是台账 ID 与公开号混用造成的假增量，正确数量为 106 篇。
2. **A 链判级偏松**：S2（能力归因）将"SHAP 健康归因"计入执行偏差归因；S3（方向化能力状态）将"数字孪生模型"、"SOC 估计"计入方向化状态；S4（跨资源承接）将"普通多资源优化"、"算力迁移"计入缺口承接。
3. **candidate_assessments 用 A 的尺子量 B/C/F**：F 候选的 gap 写成"无能力边界状态机"（这是 A 的缺口，不是 F 的缺口）。
4. **逻辑矛盾**：报告称"无文献覆盖两个及以上 S 步"，但同页列出 CN122371331A 的 S1/S4/S5=覆盖。应表述为"无文献在两个相邻连续环节同时达到覆盖级"。

### V2 修复

- 全部 JSONL 使用台账 `lit_id`（≤108），`build_matrix.py` 加入硬断言
- A 五步链收紧判定标准（§2.2 详述）
- B/C/D/F 各自使用独立判定尺子（附录 A）
- 08 号改为八章结构，A 仅是其中一章
- 定量统计仅基于 106 篇分母
