## 1. 证据三分制（冻结）

自本报告起，文献库所有条目按下表三级标注证据等级，替代 01 号台账"全文级/扉页级/损坏"的旧二级口径（旧口径保留于台账历史，不改写历史行）：

| 等级 | 定义 | 允许的用途 | 禁止的用途 |
| --- | --- | --- | --- |
| FULLTEXT-AVAILABLE | 全文（MarkItDown 或 OCR）已入库、可检索 | 方向探索、反向聚类、A–H 映射、cheap-knockout、crowded 点识别、新候选生成、探索层 HOLD/降级 | 不得据此认定"被现有技术击穿 / FINAL STOP"；不得据此修改独立权利要求语言 |
| MECHANISM-REVIEWED | 已完成针对该文献与其相关候选的机制级深读，形成"技术对象 → 状态变量 → 触发条件 → 决策动作 → 执行对象 → 反馈/降级"拆解记录；并对相关候选的关键机制链逐环判断。**仅当文献与候选 A 相关时，附加五步链 S1–S5 判定** | 候选升降级的机制层判断、撰写"背景技术"引用 | 权利要求级区别表述的最终依据 |
| CLAIMS-VERIFIED | 独立权 + 关键从属 + 说明书关键段落已与源 PDF 对照复核（OCR 底稿不算数，须回源 PDF） | 淘汰候选、修改独立权、最近现有技术定位、答审对比 | ——（本级为文献证据上限） |

边界规则：

1. **机制扫描矩阵 ≠ MECHANISM-REVIEWED**。本报告 §3 的矩阵是 FULLTEXT-AVAILABLE 层的结构化索引增强（扫描级）：由子代理对全文做一遍定向读取并抽取固定字段，服务映射与聚类，单遍、非复核。单篇升级 MECHANISM-REVIEWED 须走矩阵"深审级别"列触发的定向深读（07 号附录队列），并落盘单篇拆解记录。
2. cheap-knockout 与淘汰分两层（**探索层 vs 法律层**）：

   **探索层淘汰**：FULLTEXT-AVAILABLE 扫描矩阵即可判定某候选方向为 LOW PRIORITY / HOLD / NOT WORTH DEEPENING（资源不再投入）。允许以 OCR 全文 + 扫描矩阵为依据。**禁止项**：不得据此出具"被现有技术覆盖"的法律结论。

   **法律层淘汰**：认定"被现有技术击穿 / FINAL STOP / 修改独立权语言"，必须对该决定所依赖的关键反例篇完成 CLAIMS-VERIFIED（回源 PDF 对照独立权 + 关键从属 + 说明书关键段落）。

   目的：避免"扫描发现拥挤 → 不敢停 → 全文逐篇核权 → 陷入精细化泥潭"。

3. OCR 已知风险清单（引用 OCR 底稿时必须意识）：公式与上下标错漏、权利要求引用关系错断、专利号/人名错字、关键否定词（"无/不/未"）漏识。06 号已记录实例："光傅充"→"光储充"、"数孙李生"→"数字孪生"。
4. 既有两篇 CLAIMS-VERIFIED 维持：CN122203352A（10 号，用户提供 CNIPA PDF 源）、CN122371331A（04 号，OCR 底稿 + 源 PDF 对照）。

## 3. 全库机制扫描矩阵（方法冻结）

**不做 106 篇逐篇精读摘要**。每篇只抽取以下固定字段，形成单张矩阵，用于回答"除了 A，还有哪些现实可做、数据够用、有专利价值的方向"：

| 字段 | 回答的问题 |
| --- | --- |
| 技术问题 | 它解决什么工程矛盾 |
| 控制对象 | PV/BESS/EV/PCS/变压器/PCC/EMS/云边/Agent/大模型/数据 |
| 输入 | 用了什么现场数据 |
| 中间状态 | 能力/资格/包络/可信度/模型状态等中间量 |
| 决策动作 | 它实际改变了什么 |
| 反馈对象 | 回写计划/参数/状态/模型/设备，或无 |
| 异常/降级 | 失败以后怎么办 |
| A五步链覆盖 | 逐环 无/片段/覆盖（口径同 01 号 §3，S5 特指边界回写，计划量滚动修正不算）；**仅当文献与候选 A 相关时填写，其余填 NA** |
| A–H 映射 | 对哪些候选真正相关（简记列表） |
| candidate_assessments | **候选级子记录**：对每个相关候选，独立给出 relation（crowded/partial-gap/inspiration/not-applicable）、disclosed（该候选维度下文献披露了什么）、gap（缺什么）、confidence（high/medium/low）。同一文献对不同候选的评价不再混入单一 crowded/gap 字段 |
| crowded 点 | 哪些元素已明显有人做（通用层，不绑定候选） |
| 可挖连接 | 哪两个已有模块之间仍缺机制（通用层） |
| 数据启示 | 我方现有数据能支撑哪部分（ACN 1min EV 会话 / M5BAT BESS 偏差残差 / OpenCEM 告警寄存器 / UCSD 微网 / benchmark+仿真） |
| 深审级别 | 无需 / mechanism / claims |

执行方式（留痕）：

- 批次清单：`literature/manifests/mechanism_scan/batches.json`（按文件大小加权装盒，单盒 ≤450KB、≤10 篇，保证子代理定向读取不溢出）。当前状态：106 篇入 19 盒（lit63 重复件、lit108 损坏件跳过），含 lit31。
- 逐盒抽取：并行子代理读取全文（专利重点：权利要求 + 技术领域/背景/发明内容，实施例抽样；论文重点：摘要/引言/方法/结论），产出逐篇 JSONL 落盘 `mechanism_scan/batch_NN.jsonl`（字段含 OCR 质量标注与不确定标记）。
- 每篇的 `candidate_assessments` 须按相关候选逐一给出独立判断，不得将不同候选的 crowded/gap 混入同一字段。
- 聚合：`literature/tools/build_mechanism_matrix.py` 合并校验 → `literature/manifests/mechanism_matrix.csv`（108 行全台账口径：106 篇实抽 + 重复件 63 指向 62 + 损坏件 108 占位）。
- 判定口径继承：五步链判级（仅 A 相关文献）、术语纪律、"可信"四义限定（01 号 §4.4）全部适用。

## 4. 进展指标切换（冻结）

自本报告起**禁止以 OCR/转换数量作为文献线进展指标**。新指标五项：

1. 发现多少 crowded 机制；
2. 找到多少尚未闭合的技术连接；
3. 产生多少新候选专利点（I、J、K…，准入见 §5）；
4. B/C/F 等存活候选被全文证据升级/降级了多少；
5. 哪些候选能用现有数据做小原型验证。

## 5. 文献反向聚类生成新候选的准入规则

衔接 13 号 §5 与候选池注册表 00 号维护规则：

1. 高频模块聚类（如 云边控制切换 / 数字孪生预验证 / 大模型物理校验 / 设备离线剔除 / 可控功率计算 / 异常数据修复 / 运行结果评估）中发现"现实工程必须存在、但文献普遍未连接好"的接口，方可立项为新候选（下一可用字母 I、J…）。
2. 新候选注册须写明：文献依据（≥3 篇 FULLTEXT-AVAILABLE 独立来源 + 各自 crowded/未连证据）、与 A–H 的正交性声明、五问初答、可验证部分（手头数据/benchmark/仿真）。
3. 新候选的法律层 FINAL STOP 同样受 §1.2 约束（须对关键反例篇完成 CLAIMS-VERIFIED）；探索层 HOLD 不要求 CLAIMS-VERIFIED。
4. 新候选不改变 A 轨状态；效果级收益结论仍须 A 轨 R5 7/7（13 号保留红线）。
