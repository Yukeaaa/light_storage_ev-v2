# 0. 文档定位与执行约束

## 0.1 本文档解决什么问题

仓库现有两份核心文档分别解决：

1. `工商业园区光储充_专利方向确定详细预实验计划书_V2.0.md`：规定 E0—E8 的实验协议、变量边界、指标和最终决策原则；
2. `预实验工程实施方案与实验设计_V1.0.md`（正文版本 V1.1）：规定工程目录、数据契约、实验模块和落盘方式。

本文档不另起实验体系，而是补齐三个此前仍不够清楚的问题：

- **先做什么、后做什么，如何避免投入很大后才发现方向不成立；**
- **每一阶段具体开发哪些模块、使用哪些数据、产出哪些文件、达到什么门槛才继续；**
- **实验结果如何直接转成专利方向，而不是只形成一堆预测指标和图表。**

## 0.2 本轮最重要的纠偏

原流程为：

```text
E0 全量工程建设
→ E1 问题强度
→ E2 可执行功率区间模型
→ E3 重分配机会
→ E4 闭环回放
```

该顺序存在明显沉没成本风险：在尚未证明“存在同池重分配机会”之前，团队可能已经投入全量数据构建和模型开发。

V2.1 将流程调整为：

```text
K0 设计与数据最小验收
→ E0-Lite 最小样本构建
→ E1-Lite 问题强度 + E3-Lite 机会审计（并行）
→ K1 早期杀伤门
→ E0-Full 全量数据冻结
→ E1-Full 机制识别 + E2 强基线/区间
→ K2 信息价值门
→ E3-Full + E4 闭环回放
→ K3 控制价值门
→ E5/E6/E7 条件实验
→ K4 专利方向门
```

其中 `E0-Lite` 和 `E3-Lite` 只是 E0、E3 的低成本子集，不改变既有 E0—E8 编号。

## 0.3 一票否决原则

候选方向必须依次通过以下七门：

| 门 | 必须回答的问题 | 失败处理 |
|---|---|---|
| G0 材料原生 | 问题是否来自已有光储充材料中的充电负荷随机性、协调控制、实时调度或设备响应，而非为了算法临时构造？ | 关闭 |
| G1 场景相关 | 该问题是否真正发生在园区光储充的 EV 预算分配和执行链中？ | 关闭或收缩场景 |
| G2 可观测 | 独立方案必要输入能否由充电桩或 EMS 在线获得？ | 删除隐藏变量 |
| G3 强基线 | 持久性、滚动分位数、简单状态机或普通分配是否已经同效？ | 复杂方案降级或关闭 |
| G4 项目必要性 | 问题是否造成站级预算跟踪、交付、动作次数或储能补偿后果？ | 只作分析模块 |
| G5 可重复 | 至少两个站点、多个月份和不同字段模式下是否重复？ | 条件 Go 或缩小权利要求 |
| G6 工程成本 | 计算、通信、数据字段和部署方式是否满足实际 EMS 接口？ | 简化或关闭 |

任何核心门失败，不得用更复杂模型“救方向”。

# 1. 项目背景与前因后果

## 1.1 光储充控制链条

工商业园区光储充系统通常包含：

- 园区基础负荷；
- 光伏；
- 储能；
- 电动汽车充电设施；
- PCC/并网点；
- EMS 或站级控制器。

典型控制链为：

```text
负荷、光伏、电价、需量和设备约束
→ 站级滚动优化得到 EV 聚合功率预算与储能计划
→ 将 EV 聚合预算分配给各充电会话
→ 充电桩产生导引/允许电流
→ 车辆形成实际吸收功率
→ PCC 与储能出现真实响应
→ 下一控制周期反馈
```

真正影响 PCC 和储能的是车辆实际吸收功率，而不是充电桩额定功率、用户申报值或优化模型中的抽象上限。

## 1.2 前期项目为什么最终 No-Go

前期探索已经暴露出多类风险：

| 前期方向 | 已观察结果 | 本轮吸取的约束 |
|---|---|---|
| 用户行为预测 | 局部 MAE 可改善，但控制收益不稳定；分辨率改变时结论可能反转 | 预测指标不能替代控制价值 |
| 行为自适应 | 未稳定优于普通行为 MPC | 必须先证明新增信息价值 |
| 普通鲁棒调度 | 往往更保守，可作为强基线但不自动形成创新 | “鲁棒”本身不是专利核心 |
| A12/B1 | 不同机制在现有模型中产生相同解 | 同效立即关闭 |
| B2 保护/限制 | 合成高风险场景可降违约，但成本和削减增加，真实触发频率未知 | 真实问题频率先于算法 |
| C2 容量适配 | 严重组合漂移可检出，但公开数据不能证明真实改造决策 | 无真实决策对象时不做主方向 |

本轮因此采用：

> **问题强度优先、可观测变量优先、强简单基线优先、闭环后果优先、No-Go 优先。**

## 1.3 本轮不再采用的核心假设

以下变量不得作为独立方案的必要在线输入：

- 车辆真实 SOC；
- 准确剩余需求电量；
- 准确未来离场时间；
- 最终 `kWhDelivered`；
- 未来 `doneChargingTime`；
- BMS 内部限功率；
- PCS 拒绝原因；
- 现场真实指令拒绝码。

用户申报的 `kWhRequested` 和 `requestedDeparture` 只能作为可选、带可信度的信息源，不得等同于真实需求。

- JPL 会话级中位偏差约 -5.3%，p95 较高，聚合可用但必须做离群和电压假设敏感性；
- 4,192 个文件少于 10 行；
- 7 个 gzip 文件尾部存在垃圾但可恢复；
- 2019-12、2020-02、2020-04、2020-12 为低覆盖或异常月份；
- 2021 年无静态时序覆盖。

## 2.4 可以证明与不能证明

### 可以直接证明

- 实际电流/功率在不同充电阶段的短时演化；
- pilot 可用样本中导引/允许电流与实际响应的差异；
- 自然 pilot 变化后实际响应的经验分布；
- 不同站点、月份、字段模式下的可重复性；
- 简单历史规则是否足以预测未来实际吸收功率；
- 逻辑控制池内是否同时存在响应差异与其他活跃会话；
- 反事实功率分配在经验证响应模型中的效果。

### 不能直接证明

- 现场 EMS 指令被拒绝；
- BMS/PCS 限功率原因；
- ACN 逻辑池一定共享同一变压器或功率预算；
- ACN 与 UCSD 是同一实际现场；
- 自然 pilot 阶跃等同于随机干预；
- 用户真实满意度或“保证满足真实需求”。

所有结论必须保持上述边界。

# 3. 候选专利方向与假设树

## 3.1 第一候选 D1-R

### 临时题名

**一种基于充电响应状态识别的短时可执行功率区间生成及光储充站功率修正方法**

### 技术链

```text
采集当前及历史实际响应
→ 识别充电响应状态
→ 生成未来短时实际吸收功率区间
→ 将区间作为会话分配约束
→ 检测预算与实际响应差值
→ 在支持域内进行预算修正或同池重分配
→ 使用实际响应更新状态
```

### 两种可能落点

**D1-P：保护型**

当自然 pilot 正阶跃不足以支持主动增配时，仅主张：

- 识别未来实际吸收功率上界；
- 避免把预算分给短时无法吸收的会话；
- 将预算差值返还站级调度或储能计划。

**D1-A：主动重分配型**

只有在历史支持域内证明：

- 正 pilot 变化对应稳定正响应；
- 同池存在其他可吸收会话；
- 重分配产生闭环收益；

才主张同池回收和再分配。

## 3.2 第二候选 D2-R

### 临时题名

**一种基于充电会话多源信息可信度分级的控制约束生成与回退方法**

候选信息源：

- 用户申报；
- pilot；
- 实际电流/功率；
- 充电状态；
- 历史规律；
- 数据质量。

D2-R 只有在“不同信息可靠性确实造成控制损失，且可信度门控优于统一保守策略”时升级为独立方向；否则作为 D1-R 的支撑模块。

## 3.3 第三候选 D3-R

### 临时题名

**一种基于场站与数据模式适用度的充电响应模型选择和控制模式切换方法**

它要证明：

- 跨站或字段模式存在负迁移；
- 适用度可以在使用模型前识别；
- 模式切换改善最差场景；
- 优于按站独立模型和普通模型集成。

否则只作为工程回退机制。

## 3.4 结果树

| E1 响应问题 | E3 机会 | 正阶跃支持 | 模型信息价值 | 闭环价值 | 决策 |
|---|---|---|---|---|---|
| 不成立 | 任意 | 任意 | 任意 | 任意 | D1-R No-Go |
| 成立 | 不成立 | 任意 | 任意 | 任意 | 收缩为响应审计/上界保护模块 |
| 成立 | 成立 | 不足 | 有 | 有 | D1-P 保护型候选 |
| 成立 | 成立 | 充分 | 无 | 任意 | 使用简单规则；评估是否仍有步骤组合价值 |
| 成立 | 成立 | 充分 | 有 | 无 | 模型模块有效但不作控制主专利 |
| 成立 | 成立 | 充分 | 有 | 有 | D1-A 主动重分配主候选 |
| D1 失败 | D2/D3 独立控制价值成立 | - | - | 有 | 转入 D2-R 或 D3-R |
| 全部不成立 | - | - | - | - | 本轮专利方向 No-Go |

# 4. 总体执行策略：四个阶段门

## 4.1 K0：设计和数据最小验收门

**目的：**确保任何后续结果都可复算，但不建设完整平台。

**最大投入：**2 个工程日。

必须完成：

1. 冻结当前协议版本和 commit；
2. 确认 `acn_project` 核心文件存在并可读取；
3. 校验 matched 数、站点数、Gold 文件数和关键质量统计；
4. 建立 K1 预注册配置；
5. 选定最小 pilot-rich 样本和逻辑控制池；
6. 实现未来信息泄漏自动检查；
7. 明确绝对路径、数据版本和输出目录。

K0 不做：

- 全量 4.49 亿行重建；
- 通用仿真平台；
- 复杂模型；
- UCSD 联合优化；
- 专利撰写。

## 4.2 K1：问题与机会早期杀伤门

**目的：**在投入模型开发前确认“问题存在且有控制机会”。

并行执行：

- E1-Lite：非尾段持续响应差异；
- E3-Lite：同逻辑池并发和潜在修正机会；
- P0：专利近邻杀伤性初筛。

**最大累计投入：**K0 后追加 3—5 个工程日。

只有三者均不过早否定，才启动 E0-Full。

## 4.3 K2：新增信息价值门

**目的：**确认 D1-R 方法相对强简单基线存在独立信息价值。

执行：

- E1-Full：状态与自然 pilot 阶跃机制；
- E2：实际吸收功率区间；
- current-only 回退；
- 跨站和跨月验证。

未通过时：

- 不再做复杂模型；
- 保留最强简单规则；
- 重新判断其是否仍具有完整技术步骤组合。

## 4.4 K3：闭环控制价值门

**目的：**确认方法改善实际控制结果，而非只改善预测指标。

执行：

- E3-Full：严格机会量化；
- E4.1：响应仿真器验证；
- E4.2：反事实分配；
- E4.3：闭环预算修正；
- 压力和失败案例审计。

未通过时：

- D1-R 不作主控制专利；
- 可保留区间生成或可信度模块。

## 4.5 K4：专利方向门

综合：

- 七门结果；
- 近邻技术检索；
- 完整步骤组合；
- 可实施性；
- 技术效果；
- 跨站复现；
- 权利要求必要输入。

输出只能为：

- 主方向 Go；
- 条件 Go，限定场景和权利要求；
- 从属模块；
- No-Go。

# 5. E0-Lite：最小数据与实验骨架

## 5.1 目标

不重新建设全量数据平台，直接利用现有 `acn_project` 产物，在最短时间内形成 E1-Lite/E3-Lite 所需数据。

## 5.2 样本选择

建议第一批：

- 站点：Caltech + JPL；
- 逻辑池：各选至少 1 个 pilot 覆盖较高、并发会话较多的 site/cluster；
- 月份：从正常覆盖月份中选 6 个月；
- 会话：至少 500 个合格会话；
- 主粒度：1 分钟；
- 辅助粒度：5 分钟；
- Office001：不用于阈值选择，只留外部验证。

选择标准必须在读取测试结果前冻结：

- pilot 覆盖率；
- matched 比例；
- 会话数；
- 并发充电周期数；
- measured/computed 功率比例；
- 非异常月份。

- 选样规则和月份在 `k1_preregister.yaml` 固化。

# 6. E1-Lite：真实问题强度审计

## 6.1 目标

回答：

> 在排除初始爬升、充电完成尾段、数据缺口和异常文件后，导引/允许电流与实际响应之间是否存在重复、持续、具有量级的差异？

## 6.2 在线状态与离线排伪

### 在线可用状态

- 当前和历史实际电流/功率；
- 当前和历史 pilot（存在时）；
- 已连接时间；
- 当前数据缺口；
- 当前状态字段（存在时）。

### 仅离线排伪

- `doneChargingTime`；
- `disconnectTime`；
- 最终 `kWhDelivered`；
- 会话末端位置。

离线标签只用于判断观察到的差异是否主要发生在正常尾段，不能作为预测输入。

## 6.3 差异定义

对 pilot-rich 样本：

\[
r_{i,t}=\frac{I^{actual}_{i,t}}
{\max(I^{pilot}_{i,t},\epsilon)}
\]

\[
g_{i,t}=\max(P^{pilot}_{i,t}-P^{actual}_{i,t},0)
\]

候选持续差异事件需同时满足：

1. 车辆处于有效充电阶段；
2. `pilot` 高于最小工作阈值；
3. `r` 低于预注册阈值，或 `g` 高于绝对功率阈值；
4. 持续至少 `T_event`；
5. 不处于初始爬升窗口；
6. 不处于离线识别的完成尾段；
7. 数据质量合格。

## 6.4 阈值网格

阈值不得在测试集上逐图调整。建议训练/验证网格：

- `P_on`: 0.3 / 0.5 / 1.0 kW；
- `δ_r`: 0.10 / 0.20 / 0.30；
- `δ_p`: 0.3 / 0.5 / 1.0 kW；
- `T_event`: 3 / 5 / 10 分钟；
- 初始排除：3 / 5 / 10 分钟；
- 尾段离线排除：5 / 10 / 20 分钟。

## 6.5 指标

- 合格会话事件率；
- 每会话事件次数；
- 事件持续时间 p50/p75/p95；
- 事件内功率差 p50/p95；
- 差值能量；
- 差值占会话交付电量比例；
- 站点、月份、桩点分层；
- 去除单一桩/单一月份后的稳健性；
- current-only 数据中的对应功率衰减状态频率。

## 6.6 负对照

必须运行：

1. 尾段完全排除；
2. 时间标签随机置换；
3. 仅 Power/Voltage×Current 实测子集；
4. 排除短文件；
5. 排除 JPL 能量离群；
6. station 固定效应；
7. 异常月份单独报告。

## 6.7 K1 中的最低工程停止线

以下数值是项目投入控制线，不是行业事实。正式运行前可讨论一次，之后冻结。

- 至少 2 个逻辑池、6 个正常月份、500 个合格会话；
- 至少 5% 合格会话出现一次非尾段、持续不少于 5 分钟的事件；
- 事件功率差中位数至少 0.5 kW，或占当前工作功率至少 10%；
- 不能由单一桩或单一月份贡献超过 50%；
- 负对照后事件率仍保留主要量级。

达不到时，D1-R 主方向立即 No-Go。

# 7. E3-Lite：同池机会早期审计

## 7.1 目标

在尚未开发预测模型前回答：

> 响应差异发生时，同一逻辑控制池是否经常存在其他活跃车辆，以及强简单规则后是否仍存在值得控制的预算修正机会？

## 7.2 控制池证据等级

| 等级 | 定义 | 本轮允许表述 |
|---|---|---|
| P0 | 同时出现的统计分组 | 并发组 |
| P1 | 同 site/cluster 或明确同车库 | 逻辑控制池 |
| P2 | 有设备或拓扑证明共享预算 | 可控功率池 |
| P3 | 有真实 EMS 接口和现场回放 | 现场控制池 |

ACN 公开数据当前最多支持 P1。报告中必须称“逻辑控制池的反事实机会”。

## 7.3 早期机会定义

在不假设主动提高 pilot 的阶段，只计算保守修正机会：

1. 某会话出现持续实际响应低于其预算代理；
2. 同池另有活跃会话；
3. 其他会话当前响应稳定，且其历史实际功率上界高于当前分配代理；
4. 调整不超过历史观察支持域。

预算代理按以下强基线分别构造：

- A0：平均分配；
- A1：按当前 pilot 上限比例；
- A2：上一周期实际功率；
- A3：滚动高分位；
- A4：`min(pilot, rolling_quantile)`。

## 7.4 指标

- 差异事件发生时的并发会话数；
- 存在其他活跃会话的比例；
- 强基线后仍有余量的周期比例；
- 每日潜在修正能量；
- 潜在修正量占当日 EV 能量；
- 机会集中度；
- 不同池和月份方向一致性；
- pilot 缺失时的保守机会。

## 7.5 K1 停止线

- 强简单基线后，机会至少出现在 1% 的有效控制周期；
- 至少两个逻辑池的日潜在修正能量中位数达到当日 EV 能量的 0.5%；
- 上一周期实际功率或滚动分位数不能消除 80% 以上机会；
- 机会不能只来自单一月份或极少数离群事件。

任一关键条件不满足：

- 不开发“回收重分配”复杂方案；
- D1-R 收缩为保护型上界或关闭。

## 7.6 输出

- `e3_lite_pool_opportunity.parquet`
- `e3_lite_baseline_comparison.csv`
- `e3_lite_concentration.csv`
- `e3_lite_fail_cases.csv`
- `E3_Lite_gate.md`

# 11. E1-Full：响应状态与自然 pilot 机制

## 11.1 七类状态

1. 未连接/无效；
2. 初始爬升；
3. 稳定充电；
4. pilot 约束候选；
5. 车辆侧降流/限制候选；
6. 充电完成尾段；
7. 间歇或异常。

状态算法必须同时提供：

- pilot-rich 版本；
- current-only 回退版本；
- 规则状态机基线；
- 可选轻量分类模型。

## 11.2 自然 pilot 阶跃事件

识别条件：

- 阶跃前稳定；
- pilot 变化幅度超过阈值；
- 阶跃后观察窗口完整；
- 不在会话开始或结束附近；
- 无严重缺口；
- 当前状态处于训练支持域。

输出：

- 响应方向；
- 增益；
- 延迟；
- 饱和概率；
- 增量能量；
- 按站点、功率段、连接时长和状态分层。

## 11.3 因果表述边界

自然历史阶跃只能支持：

> 在已观察状态和 pilot 变化范围内的经验响应关系。

不得表述为：

> 任意提高 pilot 都能获得同等额外功率。

## 11.4 支持域

增量模型仅在以下全部满足时使用：

- 当前状态落在训练样本覆盖区；
- pilot 变化幅度位于历史范围；
- 有足够相似样本；
- 不确定度低于阈值。

超出支持域时：

- 不进行主动增配；
- 回退到当前实际功率、滚动分位数或保护型上界。

# 12. E2：实际吸收功率区间与强基线

## 12.1 任务定义

任务一：在当前或延续导引条件下，预测未来 1/5/15 分钟实际吸收功率区间。

任务二：在自然 pilot 变化支持域内，预测功率增量、响应延迟和饱和概率。

二者不得混为“车辆物理最大能力”。

## 12.2 强基线顺序

1. 当前功率持久性；
2. 上一周期实际功率；
3. 最近窗口均值；
4. 最近窗口最小值；
5. 最近窗口分位数；
6. 当前 pilot 上限；
7. `min(pilot, rolling_quantile)`；
8. 简单状态机；
9. 线性/分位数回归；
10. 轻量树模型。

只有轻量模型明显不足且有控制价值时，才考虑复杂时序模型。

## 12.3 主要指标

- MAE、RMSE；
- 高估功率电量；
- 低估功率电量；
- 区间覆盖率；
- 区间平均宽度；
- Winkler/区间评分；
- 偏差事件子集；
- current-only 子集；
- 跨站和跨月；
- 运行时间。

主指标不是 MAE，而是：

> **相对最强简单基线减少可执行功率高估，同时不通过无限加宽区间获取覆盖率。**

## 12.4 K2 门

相对最强简单基线：

- 高估功率电量相对下降至少 10%；
- 必须同时报告有意义的绝对下降；
- 95% 配对 bootstrap 置信区间下界不跨 0；
- 至少两个逻辑池方向一致；
- 区间宽度增幅受控；
- current-only 回退可用；
- 运行时间满足控制周期。

未通过时：

- 复杂模型 No-Go；
- 使用简单状态机或滚动分位数；
- 继续评估简单步骤组合是否仍有专利空间。

# 13. E3-Full：严格机会量化

## 13.1 三类量

### 预算差值

\[
P^{gap}_t=\sum_i\max(P^{alloc}_{i,t}-P^{actual}_{i,t},0)
\]

### 历史支持域内的其他会话余量

\[
P^{headroom}_t=\sum_j
\max(P^{supported}_{j,t}-P^{alloc}_{j,t},0)
\]

### 有效修正量

\[
P^{redis}_t=
\min(P^{gap}_t,P^{headroom}_t,P^{pool\_margin}_t)
\]

若没有共享预算证据，`pool_margin` 为反事实场景参数，不能声称现场实测。

## 13.2 预算场景

至少覆盖：

- 低约束：预算为自然实际峰值的 90%；
- 中约束：80%；
- 高约束：70%；
- 需量约束事件；
- PV 富余事件；
- 储能功率受限事件。

预算场景必须在测试前冻结，不能根据结果选取。

## 13.3 输出

- 机会率；
- 有效修正功率和能量；
- 机会持续时间；
- 集中度；
- 对预算强度的敏感性；
- 简单上界、区间上界和增量支持域的差异；
- 机会发生时的状态组合。

# 14. E4：响应器验证与闭环回放

## 14.1 E4.1 响应仿真器验证

- R1：状态机；

- 自然 pilot 阶跃方向和幅度；

- 无阶跃窗口的漂移；
- 会话能量；
- 站级并发功率。

- A1 按 pilot 上限；

- D1-P 区间保护分配；
- D1-A 支持域内主动修正；

## 14.3 控制参数

- 控制周期：1/5 分钟；
- 通信延迟：0/1/2 周期；
- 最小保持时间；
- 动作死区；
- 命令斜率；
- 最大修正轮数；
- 最小调整功率；
- 退出支持域的回退规则。

## 14.4 主指标顺序

1. 高估/未执行功率电量；
2. 站级预算跟踪残差；
3. 车辆交付电量影响；

## 14.5 K3 门

相对最强简单闭环：

- 预算跟踪残差相对下降至少 10%；

# 19. 专利方向决策方法

## 19.1 一票否决

以下任一成立，不进入主专利：

- 问题不具材料和数据原生性；
- 必要输入不可在线获得；
- 强简单基线同效；
- 只有预测指标、无控制后果；
- 只在单一月份或单一站点成立；
- 近邻已覆盖完整步骤组合且无可区分关系；
- 方法需要不合理通信、计算或字段。

## 19.2 100 分评分

| 项目 | 分值 |
|---|---:|
| 真实问题证据 | 15 |
| 场景和材料相关性 | 10 |
| 在线变量可观测性 | 10 |
| 相对强基线的信息价值 | 15 |
| 闭环控制效果 | 20 |
| 跨站/跨月复现 | 10 |
| 工程可实施性 | 10 |
| 完整步骤组合和专利区分度 | 10 |

建议：

- ≥75 分且无一票否决：Go；
- 65—74：条件 Go，收缩场景/权利要求；
- <65：No-Go 或从属模块。

## 19.3 实验到专利的映射

| 专利部分 | 对应证据 |
|---|---|
| 现有技术和工程背景 | 材料原生问题、系统控制链 |
| 关键技术问题 | E1 持续响应差异、E3 逻辑池机会 |
| 方法步骤 S1—Sn | E1 状态、E2 区间、E3 机会、E4 修正 |
| 必要输入 | 仅在线可观察字段 |
| 技术效果 | E4 预算残差、交付、动作、运行时间 |
| 适用边界 | 支持域、字段模式、池证据等级 |
| 实施例 | Caltech/JPL 多月回放；Office 外部验证 |
| 对比例 | 持久性、分位数、状态机、普通分配 |
| 从属权利要求 | pilot、申报可信度、current-only、模式切换 |

# 22. 最终执行口令

项目后续所有工作遵守：

```text
先证明问题存在
→ 再证明存在可控制机会
→ 再证明简单规则不够
→ 再建设全量数据和模型
→ 再证明闭环收益
→ 最后确定专利方向
```

任何阶段出现 No-Go，都应立即记录、关闭并释放资源。不得通过更换指标、筛选最好月份、引入复杂模型或扩大假设继续维持方向。

**本项目的最终价值不是一定形成一件专利，而是用最小可控投入，确认哪一条完整技术链真正值得形成专利。**
